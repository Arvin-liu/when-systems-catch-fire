# 第一卷第二稿修订说明

## 1. 修订对象与完成标准

本说明记录《点火百轮之后：一个跨域研究系统真正知道了什么》从初稿到第二稿的实质修订。第二稿不是初稿的复制件，也不是只替换数字的校对稿；它重新安排了读者进入问题、接触证据、看到失败和抵达未知的顺序。

- 初稿：`volume/第一卷-初稿.md`，固定基线 `9b15d359c54694d851c38df6ab3c7ae42544a51b`。
- 第二稿：`volume/第一卷-第二稿.md`，同一固定基线。
- 第二稿的正文顺序：开场账单、第一至第十章、尾声、读者后记、证据阅读约定。
- 第二稿正文约 38,000 总字符、30,000 个汉字，仍处于第一卷 30,000—60,000 汉字的规模要求内。
- 第二稿保留失败、null、撤回、降级、target absent 和统计冲突；不把它们压缩成“后来都解决了”。

## 2. 结构重写

初稿以序、十章和大量“中场”段落展开，材料覆盖充分，但后半段容易出现报告式重复。第二稿删除了任务式中场结构，建立一条新的连续路径：

1. **开场**先用 5,663/7,051 与 17,333/17,626 的并存快照，让读者立即遇到“规模不等于可解释成果”的问题。
2. **第一章**从会议白板上的小故障进入跨域相似感，说明候选生成不是外部新证据。
3. **第二章**把“解释不等于证明”改写成普通读者可以使用的四种证据区分，并用嵌套关系的简单反例说明 claim ceiling。
4. **第三章**把物理总外推、局部零读出、对象改名和撤回权写成四种不同的纠正转折，不把内部撤回写成物理共同体裁决。
5. **第四章**先讲一张卡片的生命线，再讲 Foundation 的机器快照和公共数字冲突；把登记、处置和知识分开。
6. **第五章**围绕 Function OS 的小世界、479 个预注册案例、0.9372、25 个 false reject、修复后的 bounded pass 和 oracle 独立性重写；正文用嵌套等式的直觉例子解释第一失败。
7. **第六章**把 Crossref/OpenAlex 的“找到来源不等于读过来源”提升为章节枢纽，明确 metadata、来源阅读和 claim support 的四扇门。
8. **第七章**把苹果案例从“失败复现”改为来源与目标审计：保留 bounded memoir provenance，明确 target/oracle/repeat 的缺失和任务 111 固定基线边界。
9. **第八章**把未知组织为对象、来源、运行、机制、谱系与机构化的可行动地形，而不是一串未来愿望。
10. **第九章**把“研究机构”降为待外部检验的能力组合，补入角色责任、公共可见性和维护劳动的边界。
11. **第十章**把十个方向归入外部机制/可运行边界、证据桥/历史方法、出版责任/机构化三组，并明确它们是本卷优先级判断，不是战略共识或已启动任务。
12. **尾声与后记**不重复一页全景的条目，而给读者一条可复核路线：对象、证据、版本范围、失败条件和未决证据。

## 3. 逐项处理结果

### P0 事实与主张边界

- `R-001`：开场并列写出两组 Foundation 函数/断言快照及其统计差异，明确不同范围、去重和生成快照尚未统一。
- `R-004`、`R-034`：书名中的“知道”在开头定义为“固定基线中有来源、可复核且未超过证据天花板的当前认识”；正文将“系统知道”改为本卷、研究者、固定基线或证据层能够支持的句子。
- `R-009`：物理章节明确撤回的是本项目当前的总外推，保留有限模型内的形式结果，不写成现实物理共同体的裁决。
- `R-011`：撤回权改写为研究者在系统中建立的降级、隔离、撤回和历史保留路径，不赋予系统自主意识。
- `R-013`：7,051/4,978 与 17,626/5,801 的字段含义、公开快照冲突和 claim ceiling 同段出现，明确它们不是有效函数或新知识数量。
- `R-016`、`R-017`：479 被限定为预注册有限案例；0.9372、25 个 false reject、0 false accept、0 contamination、修复版本和原始失败按版本链叙述，并加入嵌套等式的第一失败直觉例子。
- `R-019`：Crossref 117/117、OpenAlex 116 unique primary、101 supported、8 partial、7 null、0 contradicted 均先标明对象和元数据层级，不升级为正文或理论支持。
- `R-021`、`R-022`：苹果案例只保留 memoir association；target/oracle/repeat 缺失、三类案例的 target absent 及任务 111 固定基线边界均写明，不使用唯一触发、执行失败或正式完成暗示。
- `R-025`：传播和选择性物化的 Q32/Q32I 结果不在正文冒充全仓或外部证明；正文统一使用“声明范围内”“有限测试”“本地”边界，具体 Q 编号留在来源附录。
- `R-033`：`volume/来源与证据附录.md` 增加 S01–S33 的范围速查，区分单文件、文件集合、运行集合和外部返回集合，并保留证据层标签。

### P1 读者、术语与机构边界

- `R-002`、`R-003`：没有把 Git 历史规模或旧函数/案例索引数字写成样本量或当前 canonical 口径；旧编号不进入第二稿正文。
- `R-005`、`R-007`：第一章删除普遍心理学式的“我们”，改为研究者经验范围，并用会议白板上的局部故障作为非仓库生活锚点。
- `R-006`：第一章明确候选、启发式、形式模型和外部研究是不同出口，候选生成不等于新增证据。
- `R-008`：正文不再依赖 v0.1/v0.2 版本号解释读者必须理解的转折，版本和提交留给附录。
- `R-010`：第三章删除正文中的 D127/T2/D260 编号堆叠，只保留对象身份改写的事实，编号回到纠正谱系与来源附录。
- `R-012`、`R-014`、`R-015`：Foundation 章节先讲卡片生命线，再讲机器字段；把 unresolved 写成审计/注册表状态，把账本价值写成提供发现与防止回流的机会，而非保证。
- `R-018`：第六章以“找到来源，不等于读过来源”为枢纽，分开查询、匹配、阅读和主张判断。
- `R-020`：第七章正文只保留 target/oracle/repeat 三个入口，完整检查项移入案例审计和来源附录，避免正文变成报告表格。
- `R-023`、`R-024`：第八章把未知具体化，并将未来合作写为条件问题，不把机构化或外部认领写成预期结果。

- `R-028`：第十章增加三组方向说明，声明十项是本卷依据证据缺口作出的优先级判断。
- `R-029`、`R-030`：移除重复中场，首次出现的 metadata、target absent、claim ceiling 等术语先用中文解释；任务号和内部编号不承担正文导航。
- `R-031`、`R-032`：尾声保留单一人类收束，后记改为读者复核方法；整体改为稳定的无主语/研究者范围叙述。

## 4. 未完成项与故意保留的边界

内容修订项 `R-001` 至 `R-035` 已按第二稿当前文本、来源附录和提交前只读核验处理。最终核验确认本目录是独立 clone，push URL 为禁用占位值，没有新增 task 112 控制文件或 `relay/current` 文件，固定基线之外的变更只落在本出版包文件。这个事实只说明隔离和出版前置工作已完成，不说明任何正式远端仓库或任务生命周期已改变。

以下问题没有被第二稿“解决”，而是被保留为当前 claim ceiling：

1. 两组 Foundation 数字的生成口径仍需维护者解释；第二稿只并列呈现，不裁决权威。
2. Crossref/OpenAlex 仍主要是 metadata-only；全文和 claim-level 支持未被散文补写。
3. Function OS 的 bounded pass 仍不覆盖开放输入、概率、连续、神经或生产系统。
4. 苹果案例仍然是有边界来源与 target 审计，不是历史因果复现。
5. 任务 111 只按固定基线中的研究与有界案例材料引用，不作正式完成声明。

第二稿的改进不是把这些缺口变成更流畅的句子，而是让读者在正文中更早看见缺口，并知道下一项证据需要在哪里补上。
