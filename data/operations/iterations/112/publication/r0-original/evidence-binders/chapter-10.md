# Chapter 10 Evidence Binder：下一阶段最值得研究的问题

## 章节核心问题

如果不把仓库继续扩成更多模块，下一步最值得做的研究是什么？本章必须从现有缺口出发，提出能产生新证据、允许失败和可被外部审查的问题，而不是把愿景写成已经拥有的能力。

## 可支持的认识

1. 当前最重要的研究升级不是再增加一个总图，而是把候选机制放进有干预、替代解释、预注册失败标准和外部数据的研究设计。
2. 跨域对应需要从词汇/图边提升到对象、映射、结构保持、不变量和反例，并邀请各领域专家参与。
3. Function OS 的下一步若进入神经、概率、连续或分布式域，必须先定义语义、oracle、可重复性和安全边界，不能只扩展 parser。
4. 外部证据路线需要从 metadata-only 进入全文、claim-level adjudication、来源版本和复核，而不是继续累加 API 成功率。
5. 真实案例路线需要先建立 target schema；苹果案例说明没有 target 时只能做历史/叙事审计。
6. 出版路线需要统一公开/机器快照、结论—边界单页、主题笔记、三重审稿和持续修订。
7. 物理统一、暗物质/暗能量、量子引力等问题可以被列为开放研究接口，但点火不能声称自己已有答案。

## 不可支持的强说法

* 不能把本章方向清单写成已获资源、已启动工程或既定路线。
* 不能说加上干预字段就自动得到因果识别。
* 不能说全文读取自动等于主张被支持。
* 不能说更多案例会自动产生独立证据。
* 不能说出版物完成就意味着研究机构已经成立。

## 相互冲突的历史版本

|诱人的下一步|为什么需要收紧|
|---|---|
|建立一个统一跨域引擎|现有架构还是表示候选，证据制度跨领域不同|
|把所有函数接入 Function OS|scope contract 明确非符号、概率和分布式缺口|
|再抓更多 DOI|metadata-only 不解决 claim support|
|再加更多故事案例|没有 target、oracle 和替代机制会增加叙事而非证据|
|继续增加状态图|可见性冲突和人类 adjudication 尚未解决|

## 关键数字

* 目前的外部试验给出 Crossref 117/117 元数据、OpenAlex 101/116 supported、8 partial、7 null；下一步应增加证据层，而不是只增加分母。
* Function OS 当前 benchmark 479 cases；下一步要保证独立 oracle、域覆盖和失败多样性，而不是只追求 1.0。
* Foundation 有两组公开/机器计数；统一快照本身是优先研究/维护方向。
* Q31 9 groups/41 nodes 的地图可作为导航起点，但不是下一阶段研究对象的总清单。

## 反例

* 同一干预在两个领域的含义不同，若未定义单位和边界，跨域实验只是词语替换。
* 全文读到了某个结论，不说明研究设计、样本和统计支持它。
* 训练更多模型或收集更多故事不保证能区分替代机制。

## 开放问题

本章建议的十条开放路线是：

1. 设计真实系统的干预与反事实实验。
2. 建立严格跨域映射和反例协议。
3. 扩展 Function OS 前先定义非符号函数语义与 oracle。
4. 做全文/claim-level 外部来源 adjudication。
5. 建立真实案例 target presence 与失败接口。
6. 统一 Foundation 计数、快照和历史回滚。
7. 研究传播图对未知依赖的可发现性边界。
8. 建立独立领域专家和反方审查机制。
9. 评估写作/读者反馈而不循环证明。
10. 把开放物理问题交给真正的领域研究，而不是在仓库内封闭。

## Claim ceiling

本章最高是 `research_direction_proposed` 和 `open_question_prioritized`。任何方向的实现、有效性、现实机制和外部影响都未被本章证明。方向优先级依据当前证据缺口和潜在增量，不是资源承诺或结果预测。

## 可进入正文的材料

结尾应从“我们需要更多模块”转为“我们需要更难的外部问题”：一个能失败的干预、一个能被反驳的映射、一个真的读过全文的来源审查、一个有 target 的案例。这样“研究机构化”成为责任升级，而不是自我命名。
