# 研究问题谱系

## 1. 谱系说明

这张谱系不把任务编号当作思想发展史。编号只用于回到来源；真正的谱系按问题如何变形来组织。一个问题只有在遇到反例、证据缺口或工程失败后发生了可识别的改写，才算产生了一次研究转折。

点火的问题大致经历了七次移动：从“为什么不同领域看起来相似”，移动到“相似能不能被形式化”，再移动到“形式化怎样被证据限制”，接着移动到“有限执行和外部来源如何暴露失败”，最后移动到“如何把这些认识写给不熟悉仓库的读者”。每一步都留下了尚未解决的尾部。

## 2. 总体图

```text
跨域转折直觉
  -> 可比较的对象/关系/函数
  -> 相似性与同构的区分
  -> 证据制度、pending、failure、claim ceiling
  -> Foundation 的身份/处置/谱系
  -> MCF/PSD/ARN 的表示候选
  -> Function OS 的有限执行与真实缺陷
  -> Crossref/OpenAlex 的元数据实验
  -> 苹果案例的 target absent 与历史边界
  -> 传播/同步/出版层
  -> 当前未知：真实机制、领域证据、外部复制
```

这条线不是单向进步图。很多早期语言被保留为历史素材，但它们的结论高度已被降低；很多后期工程能力让边界更清楚，却没有让现实世界问题自动变得更容易。

## 3. 七条问题谱系

### A. 起源：为什么会有“点火”问题

**Q-A1：** 为什么一个领域的转折、锁定或反馈，常常让人觉得在另一个领域也见过？

* 初始材料：作者动机、诗歌/摄影/阅读/历史/组织/AI 观察、早期案例表。
* 第一次新增认识：相似感可以被拆成对象、关系、时间、反馈和边界，而不是停留在直觉。
* 现在的 claim ceiling：研究问题生成和结构化观察。
* 仍未解决：跨域相似是共享机制、表面类比，还是观察者的压缩偏好？

**Q-A2：** 一个普通叙事如何在不失去人的经验的情况下进入审查？

* 转折：叙事被拆为来源、事件、角色、转折点和可检验问题。
* 新认识：故事不是证据的敌人，但故事的流畅性会隐藏机制跳跃。
* 仍未解决：哪些叙事结构能稳定转化为不同领域都接受的研究对象？

### B. 比较：为什么能解释不等于已经证明

**Q-B1：** 共同词汇是否意味着共同结构？

* 初始答案：函数、案例、同构、跨域结构可以生成大规模候选材料。
* 纠正：对应关系必须声明对象、映射和结构保持；词语相似、图边或中心性不够。
* 当前认识：点火擅长提出候选，不擅长凭内部语言完成外部证明。
* 仍未解决：最小的跨域严格映射应当包含哪些对象和不变量？

**Q-B2：** 形式化是否会自动提高真理等级？

* 转折：Lean、SymPy、Z3 和 Foundation 使对象更清楚，也暴露有限模型的边界。
* 当前认识：形式化能验证声明模型内的命题、给出反例或显示不可满足，不会替对象获得现实语义。
* 仍未解决：如何设计能连接形式模型和领域实验、又不偷渡假设的桥接协议？

**Q-B3：** “看起来能解释”应该如何进入出版语言？

* 转折：claim ceiling 把 artifact、schema、workflow、implementation、mechanism、causal identification 分开。
* 当前认识：一句话应该携带自己的证据高度。
* 仍未解决：普通读者如何在不学习整套状态枚举的情况下理解“支持但未证明”？

### C. 约束：研究系统如何学习撤回

**Q-C1：** 为什么失败、pending 和撤回必须是系统的正式输出？

* 转折：早期强叙事遇到物理统一不可能性、零门普遍化、Gödel/Hodge 类比等问题。
* 新认识：研究系统的可信度部分来自它能主动降低自己的句子。
* 当前边界：降级改变的是当前可发布上限，不证明旧问题已经被解决。
* 仍未解决：什么样的退出机制能避免“撤回只停留在内部文件、旧句子仍在文章里回流”？

**Q-C2：** 纠正是删除历史，还是改变历史的使用方式？

* 答案：保留 old claim、纠正原因、new identity、当前 ceiling 和下游影响；历史本身成为反例和方法材料。
* 仍未解决：当同一个词在多个版本改变语义时，出版物如何既不混淆又不抹掉演变？

**Q-C3：** 注册表闭合为什么不是科学闭合？

* 转折：Foundation 从“所有函数都在表里”移动到身份、处置、证据和 quarantine。
* 新认识：可审计的会计能防止对象消失，但不能让对象变真。
* 仍未解决：人类领域专家如何参与大规模身份和主张裁决，而不被机器计数替代？

### D. 执行：Function OS 能做什么

**Q-D1：** 如果函数的声明、解析、执行和验证都被写成管线，系统能否自证？

* 初步答案：在有限符号确定性域，N1–N9 和 479-case benchmark 可以执行。
* 转折：原始 runner 的嵌套等式切分缺陷产生 25 false reject；修复后 bounded benchmark 达到 1.0。
* 当前认识：真正的工程成果是“缺陷被发现、隔离、修复、重放，原始失败仍被保存”。
* 仍未解决：神经、概率、连续、并发和分布式函数需要怎样的语义与 oracle？

**Q-D2：** 一个系统通过本地 benchmark 后，能否说它理解函数？

* 答案：只能说声明域和样本中的实现行为与 oracle 一致。
* 仍未解决：如何把 bounded benchmark 扩展到真实任务，又不把代表性假装成普遍性？

### E. 外部证据：两次元数据试验教会了什么

**Q-E1：** Crossref 117/117 的成功究竟成功了什么？

* 结果：题名/年份解析、5 个年份修正、一个有意重复保留、没有 retraction signal。
* 纠正：没有全文，没有主张支持；原先过强的“verified”状态被降到 metadata-only。
* 仍未解决：来源内容和实际论断是否与研究问题相符。

**Q-E2：** OpenAlex 的 101 supported、8 partial、7 null 是否提高了内容可信度？

* 结果：提高了 DOI 元数据匹配和 null 可见性。
* 当前认识：第二个来源让数据缺口更清晰，而不是把内容证据补齐。
* 仍未解决：4 个多 exact DOI、3 个无 exact 的 null 是源缺失、标识问题还是文献边界？需要人工/全文核验。

**Q-E3：** 外部文献回收如何改变 Function OS 的能力叙事？

* 结果：表示、规范化和部分验证有文献方向支持；神经、概率、完整规范和验证仍 partial/open。
* 当前认识：外部研究更像边界校准器，不是“文献已证明系统设计”。

### F. 现实失败：苹果案例把故事推到哪里

**Q-F1：** 历史故事何时可以成为可执行实验？

* 苹果审计显示：没有 target commit、I/O、trace、oracle、重复运行和 regression guard。
* 新认识：先确认目标存在，比先解释故事更优先；target absent 是一个有证据的结论。
* 仍未解决：如何把历史证据和可执行模拟连接起来，又不把模拟当成历史复原？

**Q-F2：** 来源能支持“苹果与重力思考有关”，是否能支持“苹果触发了万有引力理论”？

* 当前答案：不能。后来的回忆来源支持 bounded association，不能支持唯一直接触发、瞬间完整理论或流行影响。
* 仍未解决：如何处理回忆、传记、同时代来源、传播史和后见之明之间的冲突？

### G. 机构化：从研究基础设施走向研究机构

**Q-G1：** 多代理运行怎样避免把同步当作现实真相？

* Q24/Q25/Q32 提供了冷启动、远端真相、传播类型、candidate/current/merged 和回滚。
* 当前认识：仓库一致性是可靠工作的前提，不是因果证据。
* 仍未解决：外部领域合作、人工审查和现实数据如何进入同一闭环？

**Q-G2：** 读者如何不在文件和 JSON 之间跳转就看见全局？

* 当前答案：需要一个结论—边界并置的单文件入口，加上按问题组织的第一卷。
* 仍未解决：单页摘要如何既够简明，又不把所有冲突和未知压掉？

**Q-G3：** 点火目前最值得继续研究什么？

* 方向：真实干预机制、跨域映射的严格条件、Function OS 的非符号扩展、外部证据桥接、真实失败案例、计数快照统一、读者反馈的非循环评估。
* 边界：这些是研究方向，不是已承诺的模块或结论。

## 4. 关键概念的演变表

|早期说法/直觉|中间转折|当前可用说法|仍待研究|
|---|---|---|---|
|“同构”|发现类比不能替代映射和结构保持|候选 correspondence / structural analogy|严格跨域同构与反例|
|“证明”|形式工具只能在声明模型内运作|bounded formal verification / countermodel|模型—现实证据桥接|
|“函数总表”|对象身份、处置、证据被分开|function asset registry|语义质量和专家裁决|
|“全量闭合”|注册表会计与真理分开|closure by disposition/lineage|公共快照统一和语义完备|
|“因果网络”|图边/路径不能替代干预|causal candidate representation|可识别、可复制的干预预测|
|“验证来源”|Crossref/OpenAlex 只能回收元数据|metadata verified|全文、主张、领域事实核验|
|“苹果失败案例”|目标不存在不能执行|target absent; history claim bounded|真实 target 与历史模拟接口|
|“100 轮支持”|轮次不等于独立样本|longitudinal iteration history|外部独立复制和对照|

## 5. 谱系的出版意义

第一卷不能把这条谱系写成“系统越来越强”的直线。更准确的故事是：系统在材料和表达上越来越丰富，同时被一系列失败迫使承认自己知道得更少。物理 no-go 的撤回、Function OS 的 false reject、Crossref/OpenAlex 的 metadata-only、苹果的 target absent，都是认识的组成部分。它们把“知道”从答案数量改成了边界质量。

十章 evidence binder 会把谱系的每一段固定到具体来源。第二稿必须检查：每一次“因此”是否真的来自上一段证据；每一次“我们知道”是否漏掉了边界；每一个后续方向是否被误写成已经开始的工程。
