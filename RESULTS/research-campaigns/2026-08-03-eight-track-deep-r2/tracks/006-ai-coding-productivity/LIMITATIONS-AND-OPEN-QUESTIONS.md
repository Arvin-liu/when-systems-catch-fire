# 006 限制与开放问题

1. 论文和当前公开仓库的 post-review 计数不一致：论文写 27 个未审查 issue，锁定 CSV 有 16 个缺失值。当前主回归可以复现，但不能确认两者的样本版本完全相同。
2. `external_resource_needs_1_to_3` 出现一个值 5；字段定义写 1–3。主结果对排除该行不敏感，但异质性解释受到编码质量限制。
3. METR 只有 16 名开发者，246 个重复任务；开发者固定效应点估计仍为正但聚类区间跨零。任务级数量不能替代开发者级外推。
4. METR 的公开数据是同源研究的内部复制入口；CMU 镜像与原始 CSV 字节相同，尚无外部团队对同一任务数据的独立复制。
5. Microsoft 的原始 developer-week 数据没有在本轮无条件取得。INFORMS replication files 页面要求协议同意和身份字段；公开附录可审读，但不能冒充原始数据重算。
6. Microsoft 的合并结果是 weekly PR 产出和采用者 LATE；它不等于完成时间，也不等于全体获得访问权的 ITT。企业、鼓励方式、控制开放时间和工作流差异无法由三个环境系统识别。
7. GitHub 的时间结果只分析 70 名完成者，未完成者的时间被删失；没有可从正文恢复的全体 95 人时间估计。
8. GitHub 没有代码质量、返工、审查、维护或安全结果；Microsoft 的质量也只是多个有噪声代理；METR 的审查后时间不是长期质量。
9. 三项研究跨越 2022–2025 年，工具、模型和 agent 形态不同；不能把工具代际当作已证明的因果解释。
10. 论文和机构博客存在利益关系与同源传播；新闻或博客只作为问题触发和体验背景，没有承担科学结论。

外部审定时最值得优先核查的是：论文 27/CSV 16 的版本映射、Microsoft replication files 的受限数据复现、以及同一开发者在熟悉维护任务和固定新任务上的共同工具随机实验。
