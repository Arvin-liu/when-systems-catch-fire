# 项目架构（2026-07-09 元协议生成层版本）

本文是点火项目当前整体架构的权威说明。它是版本升级（而非小修小补）：项目本体从「元函数判定框架」进化为「元协议生成框架」。

## 当前整体架构

```text
点火项目 =
  Ψ₀ 元判定与收敛框架        （保留，不替换）
  + 12 元协议理论生成层       （P_meta 的向下展开）
  + 64 组合理论空间           （V×S×E = 64，理论生成空间）
  + 统一函数总表资产库        （已审核函数，D/MF/A/T）
  + 统一案例总表资产库        （已审核案例，C 编号）
```

## Ψ₀ 的角色
Ψ₀ 是总判定与收敛框架，由六个构件组成：`C(x,y) × M(B_n) × I_iso(A,B) × L_meta × G_δ × P_meta`。它输出 `true / false / contradiction / pending` 四象限结论，负责因果判定、自举收敛、同构识别、层级选择、十二律归类与元协议判定。原 `0001-Ψ₀元函数完整数学定义.md` / `docs/phi_meta_law.md` 在本次版本升级中**未改写**。

## P_meta 的展开
`P_meta` 原先是 Ψ₀ 内检查局部规则、均衡、涌现、自组织的判定算子（6 个协议判定子）。2026-07-09 起，它获得展开层：其元协议投影算子展开为 12 个基础元协议（价值 V1–V4 / 结构 S1–S4 / 演化 E1–E4），构成理论生成层。

> 重要区分：Ψ₀ 内 `P_meta` 的 6 个判定子 ≠ 本次新增的 12 个基础元协议。前者是判定（是否出现元协议结构），后者是生成（具体理论形态）。二者不混。

## 12 元协议三维结构
- 价值维度 V：V1 延续性、V2 效率性、V3 创新性、V4 可持续性。
- 结构维度 S：S1 封闭边界、S2 开放边界、S3 层级、S4 网络。
- 演化维度 E：E1 线性、E2 非线性、E3 循环、E4 收敛。

## 64 组合矩阵
V×S×E = 4×4×4 = 64 条组合，每条含「现实案例」与「推论形态」两类。它是**理论生成空间**，不是经验穷尽；逻辑矛盾的组合保留为推论形态，不强行配现实案例。数据见 `data/meta-protocols/meta-protocol-combinations.json`。

## 两张表资产库
统一函数总表（当前 617 函数）、统一案例总表（当前 804 案例）是已审核资产库，独立于候选层。候选函数 / 候选案例 / 候选元协议须经复核、补齐字段、标注 pending 后才入表。

## data / templates / outputs / audit 角色
- `data/meta-protocols/`：机器可读的 12 元协议 + 64 组合 + 22 候选 JSON。
- `templates/`：元协议条目 / 组合 / 书籍候选模板，支持后续继续产出。
- `outputs/book-collisions/`：候选暂存（22 本书案例）。
- `outputs/audit/`：审计文件，证明未越界。
- `tools/validate_meta_protocols.py`：校验 12/64/22。

## 得到大脑与 Agent 的协作方式
得到大脑（Get 笔记）产出书籍/学科碰撞候选材料 → `1111` 中转仓库暂存 → 点火主仓库审核入表。Agent 执行任务前读 AGENT-GUIDE，用 1111 作指令/结果中转，跑校验器，写审计。详见 [docs/GET-BRAIN-WORKFLOW.md](./GET-BRAIN-WORKFLOW.md)。

## 为什么这是版本升级而不是小修小补
- 项目本体形态变化：新增生成层（12 元协议 + 64 空间），第 0 层形成双结构。
- 全量文档升级：README、SUMMARY、llms.txt、架构/使用/Agent/得到大脑/版本说明统一刷新。
- 入口与导航重构：人类与 AI 入口分离且互链。
- 红线制度固化：候选不入表、元协议不计入函数总数等写入多处文档。
