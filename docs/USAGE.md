# 使用说明（人类读者）

> 当前版本：2026-07-09 元协议生成层版本。

## 1. 从 README 开始
先读 [README.md](./README.md) 的「项目定位与边界」「架构总览」「快速入口」三节，理解项目本体与边界。

## 2. 如何使用 12 元协议
打开 [docs/meta-protocols/12-meta-protocols.md](./meta-protocols/12-meta-protocols.md)。12 个元协议是理论生成层的三轴坐标（价值 / 结构 / 演化）。当你想生成或归类一个理论形态时，先选一个 V、一个 S、一个 E。

## 3. 如何使用 64 组合矩阵
打开 [docs/meta-protocols/meta-protocol-64-combination-matrix.md](./meta-protocols/meta-protocol-64-combination-matrix.md)。每条组合有「现实案例」与「推论形态」两类；推论形态（尤其逻辑矛盾者）是理论推演，不是经验穷尽。

## 4. 如何查看两张表
- 函数：[统一函数总表/INDEX.md](../统一函数总表/INDEX.md)
- 案例：[统一案例总表/INDEX.md](../统一案例总表/INDEX.md)
两张表是已审核资产库，与候选层分离。

## 5. 如何提交候选
- 候选函数 / 案例：按 [docs/two-tables-entry-writing-standard-20260709.md](./two-tables-entry-writing-standard-20260709.md) 的模板补齐字段，标记 pending。
- 候选元协议：按 [templates/meta-protocol-entry-template.md](../templates/meta-protocol-entry-template.md)。
- 书籍候选：22 本已在 [docs/meta-protocols/book-validation-22-cases-20260709.md](./meta-protocols/book-validation-22-cases-20260709.md)，未分配 C 编号。

## 6. 如何理解 pending
pending = 证据不足、暂不收敛。框架内部推论不等于外部定理；任何强断言都要保留 L0–L5 / pending / evidence 边界。

## 7. 如何避免误用
- 不要把点火当成科学/数学证明工具。
- 不要把 64 组合当成现实全枚举。
- 不要把 12 元协议当普通函数。
- 不要把候选案例当成正式案例。
