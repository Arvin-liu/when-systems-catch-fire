# Compression Integrity Gate

Status: `121Q13_CONTROL_OVERLAY`

The Compression Integrity Gate checks whether a new concept, term, or function family is a useful cognitive chunk or only a label.

It does not decide truth. It decides whether a concept is safe to promote into canonical architecture language.

## Four Checks

### Expandability

Can the term be expanded without using itself or nearby project jargon?

The expansion must identify:

- sources;
- variables;
- paths;
- conditions;
- failure boundaries.

### Generativity

Can the term generate new, distinguishable questions, predictions, tests, or objections that were not already obvious?

If it only restates the same conclusion, it is not generative.

### Compression Utility

Does the term reduce later operating burden while remaining expandable back to details?

Compression must not hide missing evidence.

### Inquiry Continuation

Does the term open better next questions?

If it ends discussion by sounding complete, it fails this gate.

## Failure Labels

- `LABEL_ONLY`: a name without expandable structure.
- `PSEUDO_CHUNK`: a term that feels compact but cannot restore details.
- `MEGA_ATTRACTOR`: a term that absorbs too many unrelated cases.
- `NON_GENERATIVE_COMPRESSION`: a term that does not produce new questions or tests.

## Relationship To Other Planes

- Effectual action chooses candidate action.
- Mechanism adjudication constrains candidate explanation.
- Attention control checks whether another loop adds information.
- Distribution control prevents one output from monopolizing interpretation.
- Compression integrity decides whether a concept may enter canonical publication language.

Passing this gate is not proof of external fact, mechanism truth, or theory upgrade.
