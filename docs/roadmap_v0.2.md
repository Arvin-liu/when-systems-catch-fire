# v0.2 Roadmap：结构缺漏审计与学科理论核二次细化

## 定位

v0.1-public-prototype 完成了项目公开化入口、使用指南、边界声明、断言等级、反证机制、贡献指南和致谢。

v0.2 的目标不是继续扩展材料库，也不是立刻跑新闻、文章、书籍和课程，而是回到框架自身，完成一次结构缺漏审计。

## 为什么暂时不下沉到新闻、文章、书籍和课程？

新闻、文章、书籍和课程属于材料层。它们可以为点火框架提供大量案例和修正机会，但如果在结构协议没有稳定之前直接大规模导入，项目会重新膨胀为材料库。

v0.2 优先处理的是：

- 框架自身的对象定义；
- 系统边界；
- 函数层级；
- 证据制度；
- 失败类型；
- 学科理论核；
- AI 输出协议。

## v0.2 的七项任务

### 1. 结构缺漏审计

检查点火框架当前是否存在以下缺漏：

- 对象定义不稳定；
- 系统边界不清；
- 函数层级关系不明；
- 断言等级未嵌入旧内容；
- 证据制度缺失；
- 失败案例无法反向修正函数；
- 高风险领域边界不足；
- AI 输出过度推论。

### 2. 函数依赖图

梳理：

- 元函数；
- 统一函数；
- 执行函数；
- 判定函数；
- 案例函数；
- 重复函数；
- 上位/下位函数；
- 缺失函数。

目标是建立 Function Dependency Graph。

### 3. UNESCO 学科理论核二次细化

不直接跑新闻材料，而是对每个学科生成“学科理论核卡片”。

每张卡片回答：

- 本学科研究什么对象？
- 核心问题是什么？
- 主流理论结构是什么？
- 证据制度是什么？
- 解释剩余是什么？
- 点火框架可映射哪些函数？
- 点火框架哪里不能解释？
- 当前断言等级是什么？

### 4. 证据制度库

不同学科的“成立”标准不同。

需要区分：

- 数学证明；
- 物理实验与数值预测；
- 历史史料链；
- 社会科学数据与反事实；
- 工程可实现性；
- 医学临床证据；
- 法律规范与程序；
- 艺术和文学解释共同体。

### 5. 失败类型学

失败案例不应只是记录，还应反向更新框架。

失败类型包括：

- 材料错误；
- 边界选错；
- 尺度错配；
- 函数过度泛化；
- 同构误判；
- 证据等级不足；
- AI 过度解释；
- L2 推论误写成 L5 结论。

### 6. 经典问题基准集

暂时不跑日常新闻，优先跑各学科经典问题。

基准集用于测试：

- 点火框架在哪些问题上有结构增益；
- 哪些地方只是重述；
- 哪些地方会失败；
- 哪些地方需要 pending。

### 7. 故事化案例 backlog

故事与案例板块会长期动态扩展。

v0.2 只建立 backlog 规则：

- 哪些案例适合故事化；
- 哪些案例代表核心函数；
- 哪些案例适合普通读者；
- 哪些案例应作为失败案例；
- 哪些案例应等待更多证据。

## v0.2 完成标准

v0.2 完成时，应至少具备：

- 一份结构缺漏审计表；
- 一套学科理论核模板；
- 一套函数依赖审查模板；
- 一套证据制度模板；
- 一套失败类型模板；
- README 中明确下一阶段不是下沉材料，而是结构深跑；
- CHANGELOG 中记录 v0.2 规划。
