# 失败类型学

本文记录点火项目 v0.2 阶段的失败类型学。

## 当前初稿

- [失败类型学初稿：得到大脑输出 20260706](../outputs/getbrain/failure-typology-draft-20260706.md)

## 定位

失败类型学用于回答：

> 点火框架在什么情况下会失败？失败以后如何记录、分类、定位到函数，并反向修正框架？

失败不是项目崩溃，而是框架自我修正的入口。

失败类型学不是独立文档，而是让 v0.2 任务 A-E 形成可修正闭环的机制。

## 当前覆盖的失败类型

本次初稿覆盖 12 种失败类型：

1. 材料错误
2. 边界选错
3. 尺度错配
4. 函数过度泛化
5. 同构误判
6. 证据等级不足
7. AI 过度解释
8. L2 推论误写成 L5 结论
9. 学科证据制度误配
10. 观察者位置错误
11. 把局部机制误写成全局规律
12. 把历史叙事误写成因果定律

## 高风险失败类型

以下失败类型尤其高风险：

- 材料错误；
- 边界选错；
- 尺度错配；
- 同构误判；
- 证据等级不足；
- L2 推论误写成 L5 结论；
- 学科证据制度误配。

这些失败会直接影响点火框架的可信度、断言等级和跨域推论边界。

## 失败案例反向修正机制

失败案例进入失败案例库后，应执行以下流程：

1. 判断失败类型；
2. 定位相关函数或函数族；
3. 判断应修正函数、降级函数、合并函数、删除候选，还是只改案例标注；
4. 同步更新函数表、案例表、证据制度库、AI 输出协议和 `docs` 边界说明；
5. 所有高风险修正必须由人类维护者复核；
6. 在 `CHANGELOG` 或版本记录中记录失败修正。

## 重要边界

失败类型学不是自动修改协议。

不得因为初稿中出现“降级函数”“合并函数”“删除候选”等表述，就自动修改函数表或案例表。

以下事项必须保持 `pending`，直到人类维护者复核：

- 是否删除某个函数；
- 是否合并某些函数；
- 是否将某个结构性推论升级为外部结论；
- 是否把失败类型学写成最终版；
- 函数的降级、合并、删除；
- 案例的标记为失败案例；
- 证据制度库的补充；
- AI 输出协议的补充；
- README / docs 边界说明的更新。
