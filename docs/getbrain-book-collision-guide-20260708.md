# 给得到大脑的最终操作指南（2026-07-08 封版）

> 本文档是给「得到大脑」（人 / 阅读侧）的操作说明。核心：得到大脑是**提出者**，不是仓库维护者。

---

## 一、得到大脑负责什么

你负责从阅读中产出**碰撞候选**，不需要碰任何技术基础设施。

1. **阅读书籍** —— 把你正在读的书的机制读出来
2. **提取机制** —— 这本书讲了什么底层结构、因果、反馈
3. **提出函数候选** —— 你认为这可能对应点火框架的哪个函数，或可能是一个新函数
4. **提出案例候选** —— 这本书里的具体场景、故事，能实例化哪个函数
5. **发现跨域同构** —— 这本书的机制，和你在别的领域（摄影、财商、AI、历史）看到的是不是同一个底层结构

---

## 二、得到大脑不负责什么

| 不负责 | 说明 |
|---|---|
| 判断最终新增 | 是否新增函数由 Agent/Codex 经 Ψ₀ 机制比对 + GPT 审核决定 |
| 修改两张表 | 统一函数总表 / 统一案例总表 只由 Agent/Codex 在回填轮次写 |
| 编号 | 函数编号（D5xx）、案例编号（C-xxxx）由系统分配 |
| Git 操作 | 提交、push、分支全部由 Agent/Codex 处理 |

> 你只管「读」和「提」，剩下的交给 Agent。

## 三、你只需要填一个模板

以后每读完一本书，只输出下面这个模板（照抄填空即可，**不需要写长文**）：

```
书名：
核心问题：
主要机制：
因果链：
反馈结构：
跨域同构：
已有函数：
可能新增函数：
可能新增案例：
反例：
证据等级：
pending 项：
```

字段说明：

- **书名**：你读的那本书
- **核心问题**：这本书在解决/讨论什么
- **主要机制**：它揭示的底层结构（一句话）
- **因果链**：A 导致 B 导致 C（cause → effect）
- **反馈结构**：有没有循环、自我强化、滚雪球（正反馈）、或钝化
- **跨域同构**：这个机制在别的领域也见过吗（摄影？财商？AI？历史？）
- **已有函数**：你觉得它对应点火框架的哪个已有函数（不知道就空着）
- **可能新增函数**：你觉得这可能是一个新函数（一句话描述机制）
- **可能新增案例**：这本书里的具体故事，能当案例
- **反例**：这本书里有没有「反过来」的例子（驳斥某函数 / 边界情况）
- **证据等级**：你自己的判断（强 / 中 / 弱 / 单一来源）
- **pending 项**：还有什么没想清楚的、需要更多材料验证的

## 四、模板示例（吴军《财商训练40讲》直播）

```
书名：吴军·财商训练40讲（开学典礼直播）
核心问题：普通人为什么攒不下钱、跑不赢大盘
主要机制：财富滚雪球（复利正反馈）+ 财富缓冲提升个人退出权
因果链：有积蓄 → 拒绝不合理要求底气↑ → 人生选择权↑
反馈结构：复利正反馈（职级提升收入指数增长）；恐慌抛售→亏损→更恐惧（恐惧锁定）
跨域同构：财富滚雪球 ↔ 系统正反馈 M13；10万积蓄↔退出权 A3
已有函数：M13 正反馈族 / A3 应约者退出权 / D67 恐惧锁定
可能新增函数：（空）
可能新增案例：芒格退休老人定投股指跑赢基金经理；低门槛行业长期净利润为零
反例：材料明确说"研究品味不能靠堆参数"（反刷分），不是刷分实例
证据等级：强（多案例 + 机制清晰）
pending 项：财富自由=复利+退出权 是否可上收为一般机制，待跨域验证
```

> 注意：上面这个示例里「可能新增函数」是空的——因为机制已被现有函数覆盖。这正是得到大脑该做的：**提出候选，不替系统下新增结论**。

## 五、提交方式

- 把模板填好，直接发给 Agent（聊天即可）
- Agent 会：拉取/索引你的 Get 笔记材料 → 做 Ψ₀ 判定 → 机制级边界比对 → 给出是否新增的建议 → 等你（或 GPT）审核
- 你不需要看仓库、不需要学 Git、不需要记编号

## 六、一句话总结

**你读书、提候选、找同构；Agent 判定、比对、回填、提交。各司其职。**
