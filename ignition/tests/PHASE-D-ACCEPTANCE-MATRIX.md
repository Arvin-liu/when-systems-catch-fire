## Failure-driven production fixes

The first complete D2 run exposed three narrow production gaps and one recovery-integrity gap:

1. core component-registry and topology schemas were recognized by the validator as meta changes but were absent from the planner full-rebuild set;
2. the unified validator did not independently require explicit input/output fingerprint policies;
3. recovery package `component_identity` was required but not compared with the ordered recovery records;
4. profile policy/generator paths were fail-closed as unknown, but were not explicitly named as meta-authorities in both planner and validator.

Minimal repairs were limited to `plan_incremental_execution.py` and `validate_incremental_execution.py`, with D1 fixture updates for the strengthened fingerprint contract. No planner traversal, executor behavior, lifecycle state, D3 attack asset, D4/E artifact, manifest, seal, system map, PR, or merge surface was added.
