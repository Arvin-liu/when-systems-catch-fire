# Effectual Action Plane

Status: `121Q12_OPERATION_OVERLAY`

The Effectual Action Plane is a cross-layer operating surface for choosing a next action when the goal, metric, path, or available resources are still unstable. It does not create truth, proof, or final project identity.

## Purpose

When the project does not yet know exactly what it should become next, the plane asks:

> Given the current code, data, AI budget, maintainer time, economic conditions, cooperation relationships, and open gaps, what small action can make the next state clearer?

This differs from causal planning. Causal planning starts from a stable goal and selects means. Effectual action starts from current means and selects a reversible action whose loss is affordable and whose result changes the state.

## Minimum State-Changing Action

A `Minimum State-Changing Action` is not merely the smallest task. It is the smallest action that, within affordable loss, can create at least one real state change:

- new information;
- new capability;
- real commitment from another actor;
- new evidence;
- new failure;
- a clearer next choice space.

If an action only creates agreeable language, mood, or branding without changing state, it does not satisfy this plane.

## Selection Formula

Approximate action value:

```text
action_value =
  information_gain
  + capability_gain
  + real_commitment_gain
  + option_space_gain
```

Hard constraints:

```text
loss <= affordable_loss
Charter Gate passes
stop / pivot / rollback conditions exist
```

Loss is not only money. It includes AI quota, maintainer time, sleep, attention, maintenance load, reputation risk, future lock-in, and opportunity cost.

## Explore / Exploit Router

Use `EFFECTUAL` mode when:

- target, metric, path, or stakeholder commitment is unstable;
- the most useful next result is information, capability, or state clarification;
- the action can be stopped, pivoted, or rolled back within affordable loss.

Use `CAUSAL` mode when:

- target, success criteria, resources, and path are stable enough to plan from an end state;
- the main uncertainty is execution, not what the next state should reveal.

Switching modes requires a recorded reason. Tone, enthusiasm, or pressure from a proponent is not a valid switch reason.

## Charter Gate Fields

Every action record must declare:

- affected subjects;
- expected benefit;
- expected cost bearers;
- reversibility or rollback path;
- harm visibility;
- maintainer sustainability impact;
- evidence threshold for scaling;
- refusal, stop, pivot, and rollback conditions.

The value charter can block or constrain an action even when the action would produce useful information.

## Outputs

The plane outputs action candidates and action records. It does not output:

- proof;
- empirical truth;
- final project positioning;
- automatic permission to publish strong claims.

Mechanism interpretation is handled by the Mechanism Adjudication Plane after observation and validation.
