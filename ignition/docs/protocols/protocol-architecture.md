# Protocol 层架构说明

> 配套 [README.md](./README.md)。本文件描述 Protocol 层与相邻层的关系、边界与 12 元协议分类。

## 1. Ψ₀ → P_meta → Protocol → Function → Case 的关系

- **Ψ₀** 是根判定与收敛框架，含六大组件（C / M / I_iso / L_meta / G_δ / P_meta）。**不替换、不被 12 协议替代。**
- **P_meta** 是 Ψ₀ 六组件之一（元协议投影算子），负责将跨系统同构投影到点火框架元层面，产出 6 个元协议（F_contract / F_symmetry / F_distributed_learning / F_nash / F_emergence / F_self-organization）。
- **12 元协议**（V/S/E 各 4）是 P_meta 展开后的**生成空间坐标轴**（value / structure / evolution 三个维度），描述系统演化的运行规则（"允许做什么"）。
- **64 组合**（V×S×E）是该生成空间的理论生成点，每个组合对应一种理论形态候选。
- **Function 层** 是"怎么做"的计算工具（D/MF/T/A），由协议空间实例化或独立定义。
- **Case 层** 是已验证的现实/跨域案例（C 编号），由函数层实例化支撑。

关系链：

```
Ψ₀ ⊃ P_meta（组件）
   → 12 元协议（V / S / E 坐标轴）
   → 64 组合（生成空间点）
   → Function 层实例化（D/MF/T/A）
   → Case 层实例化（C 编号）
```

## 2. Protocol 与 Function 的边界

| 维度 | Protocol（规则层） | Function（计算层） |
|---|---|---|
| 本体 | "允许做什么"（运行规则） | "怎么做"（计算工具） |
| 目标 | 约束其他函数运行 | 追求效率/确定性输出 |
| 组合性 | 互斥（如延续性 vs 创新性） | 可组合 |
| 编号 | V/S/E 独立体系 | D/MF/T/A |
| 计入 | 不计入函数数量 | 不计入协议数量 |

**协议约束函数，不替代函数；函数可引用协议，但协议不获得函数 ID。**

## 3. Protocol 与 Case 的边界

- Case 层是已验证实例（C 编号，current 至 C-809 级），由函数层支撑。
- 22 本书验证案例当前为 `candidate_only`，**不是正式案例**，不进入 Case 层编号。
- Protocol 层描述生成规则；案例验证的是函数与框架，而非协议本身作为独立资产被采纳。

## 4. 12 元协议分类

### 价值维度（V1–V4）
- V1 延续性协议：选择使系统延续时间最大（或延续概率最高）的行动。
- V2 效率性协议：以资源利用效率最大化为目标的演化规则。
- V3 创新性协议：选择使复杂度（熵）增加最大的行动。
- V4 可持续性协议：以长期动态平衡为目标，在扩张与收缩间维持循环。

### 结构维度（S1–S4）
- S1 封闭边界协议：边界严格封闭，拒绝外部输入与内部输出。
- S2 开放边界协议：边界开放，允许外部元素自由流入流出。
- S3 层级边界协议：边界按层级划分，高层可访问低层，反之不行。
- S4 网络边界协议：边界为网络形态，节点对等连接，无中心控制。

### 演化维度（E1–E4）
- E1 线性演化协议：沿单一轨迹线性推进，状态可预测。
- E2 非线性演化协议：路径非线性，小变化引发大结果。
- E3 循环演化协议：状态间循环往复，周期性重复。
- E4 收敛演化协议：向单一状态收敛，复杂度逐渐降低。

## 5. 64 组合空间

V（4）× S（4）× E（4）= **64** 组合。每个组合是生成空间中的一个理论形态候选，编号规范 `V{n}-S{n}-E{n}`（如 `V1-S1-E2`）。64 组合是**组合空间**，不是新增函数，也不进入 Function 编号体系。底层数据见 `data/meta-protocols/meta-protocol-combinations.json`。

## 6. 与 Ψ₀ 的显式区分（必须保持）

**P_meta 的 6 个产出 ≠ 12 元协议。** 12 元协议是 P_meta 展开后的生成空间坐标轴；64 组合是该空间生成点。Ψ₀ 仍负责判定（J⁺/J⁻）、同构识别（I_iso）与收敛审核（L_meta），不被替代。
