# Pending 强结论登记表

本文登记点火项目 v0.2 阶段必须保持 pending 的强结论、强问题和高风险表达。

它不是问题解决清单，也不是研究成果清单，而是公开表达前的边界治理文档。

## 1. 使用目的

本登记表用于：

1. 防止把结构性推论写成外部证明；
2. 防止把结构性增益写成问题已解决；
3. 防止把故事化案例写成证明材料；
4. 防止把跨域同构误写成学科内结论；
5. 防止在数学、物理、医学、法律、金融、社会科学、AI 安全等领域越界；
6. 帮助 README、docs、benchmark、故事化案例和对外材料统一措辞。

## 2. 总原则

点火框架可以给出：

- L0：材料整理；
- L1：结构类比；
- L2：结构性推论；
- L3：框架内部交叉验证；
- pending：尚需外部证据制度验证的问题。

点火框架不能直接给出：

- L4：数学或专业证明，除非已有外部证明；
- L5：实验、临床、法律、工程、社会科学实证或政策验证，除非已有外部证据。

没有外部证据制度支撑时，强结论默认 pending。

## 3. 统一禁止表达

以下表达在 v0.2 公开材料中禁止直接使用：

- “点火框架证明了……”；
- “点火框架解决了……”；
- “该问题已经被点火统一……”；
- “该问题已经有最终答案……”；
- “这就是数学证明……”；
- “这就是物理机制……”；
- “这就是历史真实原因……”；
- “现实政策应该据此执行……”；
- “医学 / 法律 / 金融上可以据此建议……”；
- “故事化案例证明了……”。

## 4. 统一推荐表达

推荐使用以下表达：

- “点火框架提供了一种结构性解释路径。”
- “该问题在点火框架中获得了结构性重写。”
- “该判断目前处于 L2 / L3，仍需外部证据制度验证。”
- “这不是学科内证明，而是跨域结构映射。”
- “该问题应保持 pending。”
- “该案例适合故事化展示，不适合作为证明材料。”

## 7. 公开前处理规则

公开前遇到本登记表中的问题，按以下规则处理：

| 情况 | 处理 |
|---|---|
| 只是结构观察 | 可公开，但标注 L0 / L1 |
| 是结构性推论 | 可公开，但标注 L2 / L3 |
| 涉及外部证明 | 无证明则不能写成 L4 |
| 涉及实验 / 临床 / 法律 / 工程 / 政策 | 无外部证据则不能写成 L5 |
| 涉及医学 / 法律 / 金融建议 | 默认 HOLD |
| 涉及故事化案例 | 必须注明故事化不是证明 |
| 无法判断等级 | 默认 pending |

## 8. 推荐审核结论

每个涉及 pending 强结论的公开材料，应给出以下结论之一：

| 结论 | 含义 |
|---|---|
| PASS | 可以公开，风险已处理 |
| REVISE | 可以公开前需改措辞 |
| HOLD | 暂停公开，等待证据、边界或编号修正 |
