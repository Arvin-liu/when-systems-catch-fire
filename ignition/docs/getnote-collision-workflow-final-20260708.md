# Get 笔记碰撞工作流 · 封版说明（2026-07-08）

> 本文件固化「Get 笔记材料 → 点火框架函数/案例碰撞」的准备与执行流程。
> 适用阶段：从 Get 笔记拉取材料，经分类、候选排序、Ψ₀ 判定，到回填两张表的完整链路。
> 当前阶段状态：准备阶段已收口（候选召回层已验证有效，机制级二次判定层待建）。

---

## 一、输入材料规范

| 项 | 规范 |
|---|---|
| 来源 | Get 笔记 API 全量拉取（翻页 + 客户端筛选） |
| 筛选 | `note_type == "link"` → 链接笔记；标题含「发芽报告」→ 发芽报告 |
| 排除 | 「发芽报告-相关讨论/」为元笔记（讨论发芽报告本身），**不作为碰撞材料** |
| 落盘 | 本机「我的笔记」Obsidian 库（链接笔记/、发芽报告/），**不进点火仓库** |
| 格式 | 每文件含 frontmatter：`note_id / type / source / created` + 正文 |
| 编码 | UTF-8 |
| 规模 | 本次：链接笔记 441 + 发芽报告 160 + 讨论 6 = 607 个材料文件 |

## 三、Agent / Codex 负责部分（程序侧 / 仓库侧）

- 回填两张表（经 GPT 审核后）
- Git 提交与 push

## 四、Ψ₀ 判定流程

1. **读取材料正文**（仅读，不改）
2. **三层提取**：
   - 事件层（Domain）：发生了什么具体场景
   - 机制层（Function）：中间机制是什么
   - 元层结构（Meta）：能否上收为一般机制
3. **六维判定**（每维标 触发 / 不触发 / 弱触发）：
   - **C**：是否存在明确因果链（cause → effect → temporal → counterfactual）
   - **M**：是否存在循环、自我强化、累积机制
   - **I_iso**：是否能与已有函数形成结构同构
   - **L_meta**：是否值得上收为一般机制
   - **G_δ**：是否存在证据不足或不可收敛
   - **P_meta**：是否涉及规则、激励、退出、权力、协议结构
4. **函数边界机制查重**：比较候选机制与已有函数的「触发条件 / 中间机制 / 结果形态」三者同构性

---

## 五、函数新增判定标准

- **机制级比对**：触发条件是否齐备 + 中间机制是否与已有函数**不同构** + 结果形态是否一致
- **新增门槛**：机制结构在现有函数表中**找不到同构覆盖**，且跨域证据充分
- **单条材料远不足新增**；需多域复现或真实外部材料支撑
- **必须给出闭合数学机制表达**（函数式），不接受纯文字判断
- 验证：经 GPT 审核确认后，写入 统一函数总表/ + INDEX.md 追加行 + 审计

---

## 六、案例新增判定标准

- 提供**具体场景 + 动作 + 结果**三要素
- 能实例化某条函数（作为该函数的证据/示例）
- 来源回指清晰（`note_id` / `source` / `date` 可溯）
- 验证：写入 统一案例总表/ + INDEX 追加行

---

## 七、扩展注释处理标准

- **不新增函数编号**
- 在已有函数文件的「扩展注释」段追加
- 记录跨域复现证据（领域 + 具体机制）
- 可**降低 pending 强度**，但不直接取消 pending
- 示例：D597 追加「指标排名隐性分层」扩展注释，将单篇教育证据升级为「教育 + 跨域三领域复现」

---

## 八、pending 处理标准

- **单篇 / 单域材料不足以取消 pending**
- 跨域 smoke test 三领域复现，可**降级 pending 强度**（如 D597 from 单篇 → 三领域复现）
- pending 项必须明确标注**证据状态**（单篇 / 跨域复现 / 待真实材料）
- pending 项不进入函数新增，只作为未来验证锚点

---

## 九、不采纳标准

- 关键词命中但**机制不成立**（反向语境误触发，如材料「批判刷分」被判为刷分博弈）
- 已有函数**机制同构覆盖**（召回层命中即不新增）
- 证据不足 / 不可收敛且无新机制
- 重复 / 噪音 / 元笔记（发芽报告-相关讨论）

---

## 十、回填流程（经 GPT 审核后执行）

1. GPT 确认新增 / 扩展注释 / pending 分类
2. 新增函数：写 统一函数总表/ + INDEX 追加 + 审计
3. 新增案例：写 统一案例总表/ + INDEX 追加
4. 扩展注释：在已有函数文件追加「扩展注释」段
5. **索引可见性验证**：文件存在、INDEX 可见、语义可召回、来源回指、审计闭环
6. `tools/validate_data.py` 校验通过
7. commit + push（本机局部 identity，不动全局 git config）
