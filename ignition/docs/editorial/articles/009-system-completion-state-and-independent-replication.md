# 一个系统怎样知道某件事已经做过，而不是把同一项工作再次排到未来？

> 之元方法文章 · 任务 110。本文解释一个治理与证据问题，不新增物理、数学或论文内容结论。

## 先回答问题，而不是先排队

一个系统要知道某件事是否已经做过，不能只看候选表里的一列“PRIMARY”或
“DEFERRED”。它必须把三个问题分开：这项义务是否被执行过？执行得到什么范围内的
结果？这项结果是否已经通过生命周期闭合成为当前事实？如果三件事被压成一个排序
字段，系统就会把历史工作重新包装成未来工作。

任务 109 的推荐暴露了这个缺口：`C-01` 仍被排在第一位，但它对应的
`SRC-REGISTRY-104-METADATA` 已经由任务 103 用 Crossref 完成并裁定为
`SUPPORTED_WITHIN_SCOPE`。`C-04` 仍显示为延后，但任务 105 已经完成了它的有界
Function OS 基准。这里的问题不是排序分数不够精确，而是排序器没有读取完成状态。
原始推荐因此保留为一条可审计的缺陷记录，而不是被改写成“从未推荐过”。

## 完成不等于支持

完成状态首先回答“这次预先声明的工作有没有走完”，不是回答“命题是真的”。一个
实验可以完成并得到 `SUPPORTED`、`PARTIAL`、`CONTRADICTED`、`NULL` 或 `INVALID`。
这些状态都必须留在历史中；尤其是失败、空结果和矛盾结果不能通过再次排队来假装
它们没有发生。只有在有明确的 owner 决定、改变了协议或重新定义了对象时，才可以
开一个新的候选身份或 revision。否则，系统会把“已完成但未支持”误认为“尚未开始”。

因此，任务 110 的完成登记使用候选 ID、claim ID、run/preregistration ID、task ID
和显式 supersession 关系。文字相似只能提出待人工检查的线索，不能自动证明两个
候选是同一项义务。生成的 planner queue 也不能反过来充当 completion authority。
这条边界同时保护科学重复：重复做同一项已经闭合的 Crossref 检查不是新证据，除非
问题、oracle、协议或 owner 授权发生了可说明的变化。

## 为什么 OpenAlex 是新证据，而不是重跑 C-01

`C-03` 仍使用同一批 117 条 DOI，但它提出的是不同的可核验关系：把锁定的
registry/Crossref 字段与 OpenAlex Works API 的独立返回进行逐条比较。新 oracle
使它成为跨源元数据复制，而不是把任务 103 的 Crossref 请求再执行一次。正式
预注册和 117 条人口清单先在 formal 分支独立提交、推送并验证祖先关系，之后才开始
OpenAlex 请求；原始响应、时间、状态、哈希、歧义和匹配理由都被保留下来。

首轮结果是 117/117 个 HTTP 200 JSON 响应；去除一条预先标记的重复 DOI 后，116 条
进入主分母：101 条 `SUPPORTED_WITHIN_SCOPE`、8 条
`PARTIALLY_SUPPORTED_WITH_IDENTIFIED_MISMATCHES`、0 条矛盾、7 条
`NULL_OR_INCONCLUSIVE`、0 条无效。四条多重精确 DOI 命中和三条无精确命中没有被
平均掉；九条 partial 中，主分母的八条是预注册的 online/print 一年差异。

这些数字只说明 registry/Crossref 与 OpenAlex 的书目元数据在协议规定的范围内有多
一致。它们不说明论文正文正确，不验证被引论文的科学结论，不验证 Pointfire、MCF、
PSD、ARN 或现实因果，也不提升任何物理成熟度或 disposition。OpenAlex 的可用信息
上限就是 metadata ceiling；当没有唯一 DOI 命中或所需字段不足时，诚实的输出是
null，而不是寻找一个“看起来最像”的作品。

## 当前真相要经过一条链

在仓库里，“做过”还不能由一条结果文件单独宣布。候选事件先记录任务、前驱、影响
维度和预期终态，但不预写未来 merge commit、tag 或 receipt hash；内容 PR 经过精确
head 审查并普通合并后，才可以追加终端化投影；最后由窄范围终端化 PR、不可强移动的
annotated tag、核心回执和全新克隆 resolver 共同确认 `TERMINAL_SUCCESS`。

这种两阶段结构不是仪式。它把“计划会发生什么”和“远端实际上发生了什么”分离，
让系统可以在任何一环缺失时停在 `READY_FOR_CONTENT_MERGE` 或
`AWAITING_TERMINAL_TAG`，而不是把一个尚未存在的提交号当成事实。公开页面、开放
问题、Evidence Program 和文章随后从同一组受治理记录传播；文章则必须在材料源改变
后离开 `REVIEWED_CURRENT`，经过真实复审才能恢复。

## 写作方法：把下一步交给证据，而不是交给惯性

之元方法在这里可以压缩为五个动作：先写清问题，再锁定对象；把完成、结果和当前
状态分层；给每个判断绑定可追溯身份；把 null、失败和边界写进正文；最后只让当前
证据决定下一次 owner decision。这样写出来的“完成”不是乐观语气，而是一种可复核
的状态。它既阻止重复劳动，也阻止一次漂亮的 metadata agreement 越过它自己的
信息边界，冒充对世界的更大证明。

**主张上限：** 本文解释任务 110 的完成状态修复、OpenAlex 独立元数据复制和生命
周期传播；不新增科学、数学或现实因果结论。
