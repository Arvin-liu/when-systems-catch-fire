# 公开前风险检查清单

本文是点火项目的公开前风险检查清单。

它用于检查 README、docs、benchmark、故事化案例、对外说明、文章、发布稿、社交媒体摘要等公开材料，避免把点火框架的结构性推论误写成外部证明、事实结论、专业建议或最终定论。

## 1. 使用场景

以下内容公开前必须经过本清单检查：

1. README 中的项目定位；
2. docs 中的框架说明；
3. 经典问题 benchmark；
4. 故事化案例；
5. 函数说明；
6. 案例说明；
7. 失败类型说明；
8. 对外文章；
9. 对外演示稿；
10. 社交媒体短文；
11. 任何使用点火框架解释现实问题的材料。

## 2. 总原则

点火框架可以提供：

- 结构性观察；
- 结构性类比；
- 跨域同构判断；
- 框架内部推论；
- 证据制度映射；
- 失败类型识别；
- pending 标注；
- 进一步研究的问题清单。

点火框架不能替代：

- 数学证明；
- 物理实验；
- 工程验证；
- 医学诊断；
- 法律意见；
- 金融建议；
- 历史史料考证；
- 社会科学实证研究；
- AI 安全部署评估；
- 艺术史专业考证；
- 任何高风险领域的专业判断。

## 3. 断言等级检查

公开前，所有关键断言必须判断属于哪一层。

| 等级 | 含义 | 是否可公开为结论 |
|---|---|---|
| L0 | 观察、描述、材料整理 | 可以，但不能解释过度 |
| L1 | 结构类比、初步相似性 | 可以，但必须标注为类比 |
| L2 | 结构性推论 | 可以，但不能写成证明 |
| L3 | 框架内部交叉验证 | 可以，但必须说明仍是框架内部判断 |
| L4 | 外部数学证明或专业证明 | 只有存在外部证明时才可这样写 |
| L5 | 外部经验、实验、工程、临床、法律或社会科学验证 | 只有存在对应证据时才可这样写 |

### 禁止写法

以下写法禁止直接公开：

- “点火框架证明了……”；
- “点火框架解决了……”；
- “点火框架发现了最终答案……”；
- “这个问题已经被点火框架统一……”；
- “数学上已经成立……”；
- “物理上已经证明……”；
- “医学上可以据此建议……”；
- “法律上可以据此判断……”；
- “政策上应该据此执行……”。

### 推荐写法

推荐替换为：

- “点火框架提供了一种结构性解释路径。”；
- “该问题在点火框架中获得了结构性重写。”；
- “该推论目前处于 L2 / L3，仍需外部证据。”；
- “这不是学科内证明，而是跨域结构映射。”；
- “该判断应保持 pending。”；
- “该案例适合作为故事化展示，不适合作为证明材料。”。

## 4. pending 检查

出现以下类型问题时，必须标注 pending：

1. 数学猜想；
2. 物理学强结论；
3. 历史因果具体判定；
4. 社会科学因果判定；
5. 经济学政策建议；
6. 医学建议；
7. 法律判断；
8. AI 安全、对齐、部署结论；
9. 审美判断客观性；
10. 工程可行性判断；
11. 现实政策建议；
12. 对个人行为的具体指导。

如果材料不能明确说明证据来源、证据制度、断言等级，则默认 pending。

## 5. 高风险领域检查

### 5.1 数学

公开前检查：

- 是否把结构性推论写成数学证明；
- 是否涉及黎曼猜想、P vs NP、哥德尔不完备性等强问题；
- 是否有外部证明；
- 是否明确区分“结构解释”和“数学证明”。

默认处理：

- 无证明则保持 L2 / L3；
- 不得写成 L4。

### 5.2 物理学

公开前检查：

- 是否涉及四种基本力统一；
- 是否涉及量子引力；
- 是否涉及暗物质 / 暗能量；
- 是否涉及标准模型、广义相对论、量子场论；
- 是否有实验、观测、公式或同行评议支持。

默认处理：

- 无外部物理证据则保持 pending；
- 不得写成 L5。

### 5.3 历史学

公开前检查：

- 是否把历史叙事写成单一因果定律；
- 是否忽略史料、时间、地区、制度背景；
- 是否把结构相似写成历史必然；
- 是否涉及罗马帝国衰亡、工业革命、中国王朝周期等大问题。

默认处理：

- 只能写成解释框架或问题重写；
- 不能写成历史学定论。

### 5.4 社会科学与经济学

公开前检查：

- 是否把结构模型写成实证因果结论；
- 是否涉及政策建议；
- 是否涉及现实群体、国家、阶层、性别、教育、公平等敏感议题；
- 是否有数据、模型、识别策略、反事实论证。

默认处理：

- 无实证证据则保持 pending；
- 不得给出现实政策指令。

### 5.5 医学与心理健康

公开前检查：

- 是否涉及诊断；
- 是否涉及治疗；
- 是否涉及用药；
- 是否涉及心理健康建议；
- 是否涉及个人健康决策。

默认处理：

- 不给医学诊断；
- 不给治疗建议；
- 不替代医生；
- 只可写成一般性结构观察。

### 5.6 法律

公开前检查：

- 是否涉及具体法律判断；
- 是否涉及个人、机构、合同、责任、犯罪、诉讼；
- 是否涉及现实法律建议。

默认处理：

- 不给法律意见；
- 不替代律师；
- 只可写成结构性分析。

### 5.7 AI 与计算机科学

公开前检查：

- 是否涉及 AI 对齐、安全、部署；
- 是否涉及大模型涌现；
- 是否涉及泛化能力；
- 是否把推论写成工程结论；
- 是否有实验、代码、评测、复现。

默认处理：

- 无实验验证则保持 L2 / L3；
- 不得写成部署建议。

### 5.8 文学、艺术与审美

公开前检查：

- 是否把审美解释写成客观定论；
- 是否把故事化案例写成证明；
- 是否把个人阐释写成普遍规律；
- 是否忽略历史语境、媒介条件、观看情境。

默认处理：

- 可以公开为解释路径；
- 不写成唯一答案。

## 6. 失败类型交叉检查

公开前必须检查材料是否触发以下失败类型：

1. 材料错误；
2. 边界选错；
3. 尺度错配；
4. 函数过度泛化；
5. 同构误判；
6. 证据等级不足；
7. AI 过度解释；
8. L2 推论误写成 L5 结论；
9. 学科证据制度误配；
10. 观察者位置错误；
11. 把局部机制误写成全局规律；
12. 把历史叙事误写成因果定律。

如果触发其中任意一项，公开前必须修正措辞，或标注 pending，或暂停发布。

## 7. CP / SB 编号检查

如果公开材料引用经典问题 benchmark，必须使用 CP 编号。

当前编号范围：

```txt
CP-001 至 CP-034
```

索引见：

- [经典问题 benchmark 编号索引](classic_problem_ids.md)

如果公开材料引用故事化 backlog，必须使用 SB 编号。

当前编号范围：

```txt
SB-001 至 SB-030
```

索引见：

- [故事化 backlog 编号索引](storytelling_backlog_ids.md)

检查要求：

1. CP / SB 编号必须存在；
2. 编号不能重复；
3. 编号不能临时插号；
4. 新增条目应另起补丁或新版本；
5. 公开材料中引用的标题必须与编号索引一致。

## 8. 公开前检查流程

每个公开材料发布前，按以下步骤检查。

### Step 1：确定材料类型

材料属于：

- README；
- docs；
- benchmark；
- 故事化案例；
- 文章；
- 演示稿；
- 社交媒体短文；
- 其他。

### Step 2：标出关键断言

找出材料中的关键断言，尤其是：

- “证明”；
- “解决”；
- “统一”；
- “必然”；
- “最终”；
- “规律”；
- “本质”；
- “应该”；
- “可以据此”。

### Step 3：给断言分级

每条关键断言标注：

- L0；
- L1；
- L2；
- L3；
- L4；
- L5；
- pending。

### Step 4：匹配证据制度

判断该断言属于哪个证据制度：

- 数学；
- 物理学；
- 历史学；
- 社会科学；
- 经济学；
- 医学；
- 法律；
- AI / 计算机科学；
- 文学 / 艺术；
- 其他。

### Step 5：检查失败类型

检查是否触发 12 种失败类型。

### Step 6：检查 CP / SB 编号

如果引用 benchmark 或故事化 backlog，检查编号是否存在。

### Step 7：给出发布结论

发布结论只能是以下三种：

| 结论 | 含义 |
|---|---|
| PASS | 可以发布 |
| REVISE | 需要修改措辞后发布 |
| HOLD | 暂停发布，等待证据、编号或边界修正 |

## 9. 发布前最小表格

公开前可以使用以下表格：

| 检查项 | 结果 |
|---|---|
| 材料名称 |  |
| 材料类型 | README / docs / benchmark / 故事化 / 文章 / 其他 |
| 是否涉及高风险领域 | 是 / 否 |
| 关键断言最高等级 | L0 / L1 / L2 / L3 / L4 / L5 / pending |
| 是否存在 L2 写成 L5 | 是 / 否 |
| 是否存在结构增益写成已解决 | 是 / 否 |
| 是否涉及医学 / 法律 / 金融建议 | 是 / 否 |
| 是否引用 CP 编号 | 是 / 否 / 不适用 |
| 是否引用 SB 编号 | 是 / 否 / 不适用 |
| 是否触发失败类型 | 是 / 否 |
| 处理结论 | PASS / REVISE / HOLD |

## 10. 强制 HOLD 条件

出现以下情况，必须暂停发布：

1. 把 L2 / L3 写成 L4 / L5；
2. 把结构性解释写成已证明；
3. 把故事化案例写成证明；
4. 涉及医学、法律、金融、心理健康具体建议；
5. 涉及现实政策建议但无证据；
6. 涉及数学、物理强结论但无外部证明或验证；
7. 引用不存在的 CP / SB 编号；
8. 明显触发失败类型但未修正；
9. 无法判断断言等级；
10. 读者可能误解为专业结论。

## 11. 推荐公开措辞模板

### 结构性解释

推荐：

> 点火框架在这里提供的是结构性解释路径，而不是学科内证明。

### pending 标注

推荐：

> 该判断目前应保持 pending，原因是缺少对应证据制度下的外部验证。

### benchmark 表述

推荐：

> 该问题可作为点火框架的 benchmark，用于测试框架是否能产生结构性增益。

### 故事化表述

推荐：

> 该案例适合故事化展示，但故事化不是证明，只是帮助读者理解结构关系。

### 高风险领域表述

推荐：

> 本文不提供医学、法律、金融或政策建议，只讨论结构层面的解释框架。
