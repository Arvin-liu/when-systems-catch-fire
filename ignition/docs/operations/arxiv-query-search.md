# arXiv query search candidate

`research.search_arxiv_query` is an experimental, default-off adapter for discovering up to ten arXiv records from one public, non-sensitive query. It sends one HTTPS GET to `export.arxiv.org/api/query`, requests Atom metadata in relevance order, and returns selected identifiers, titles, author names, dates, categories, journal references and DOIs. It deliberately drops abstracts and article content from the receipt.

The CLI accepts exactly `{"query":"...","max_results":1}` through bounded UTF-8 JSON stdin and requires the per-invocation `--allow-public-network` flag. The query is sent to arXiv and may be logged by the provider; the receipt contains only its SHA-256, not the raw query or request URL. There are no retries, redirects, arbitrary hosts, API credentials, writes or billing. Response bytes are limited to 512 KiB and ten records; network timeouts and provider parse failures remain explicit outcomes.

The arXiv API uses the `search_query`, `start` and `max_results` parameters and returns Atom feeds ([API manual](https://info.arxiv.org/help/api/user-manual.html)). Its terms require no more than one legacy API request every three seconds and one connection at a time across all machines controlled by the caller ([API terms](https://info.arxiv.org/help/api/tou.html)). This adapter makes one request per invocation but has no shared cross-process or cross-machine rate limiter. The caller must serialize invocations and honor the global interval; do not use this adapter for concurrent or bulk harvesting.

The task scope is topic-to-record discovery within the arXiv corpus. The existing `research.lookup_arxiv_paper_metadata` accepts one already-known modern arXiv identifier and resolves its record; it cannot discover IDs from a topic. PubMed and Europe PMC search different provider collections and have different source-specific result contracts, so they may coexist for tasks that need those indexes. Local source navigation remains preferable whenever the checked-out corpus already covers the task. No one-query comparison proves relevance, recall, reliability, cost or scientific quality; those remain unknown.

This tool does not search outside arXiv, guarantee exhaustive recall, judge relevance, retrieve abstracts/full text, authenticate a source, establish publication status, or support scientific claims. An arXiv record may be a preprint and its metadata is provider-reported. For known IDs, use the exact-ID adapter. For DOI/PMID tasks, use the corresponding provider adapter only when its output is needed.
