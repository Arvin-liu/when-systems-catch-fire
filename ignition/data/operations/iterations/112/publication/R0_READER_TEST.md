# R0 读者模拟测试

本测试是三种受限读者模拟，不是实际人类可用性研究。没有真实读者参与，因此不使用“用户验证”“读者已经理解”等词。

## 模拟一：完全不了解点火的普通读者

**进入路径：** R0 二稿开场。

**可理解部分：** “两组不一致的账单”能制造一个真实问题；“百轮不是一百次独立实验”很快建立了重要边界；第一章的会议场景帮助读者理解相似感如何进入研究。

**具体失败：** 开头在读者还不知道项目为何重要时同时放出 5,663、7,051、17,333、17,626 和多个英文状态。读者可能把数字差异误解成账本错误或成果规模竞赛；`claim ceiling`、`target`、`oracle` 在第一次出现时仍带有内部语气。后半部分的“后记”再次解释五个问题，造成全景与正文的重复。

**必修修订：** 保留数字冲突，但先用一个普通阅读场景说明“统计对象不同”；把第一次定义改成“结论天花板”“可运行目标”“判定标准”；删除二稿标签和内部版本姿态；把复核练习压缩为正文结尾的一段，并让单文件全景承担清单职责。

## 模拟二：想要全局结果的项目所有者

**进入路径：** 先打开 R0 全景，再打开二稿。

**可理解部分：** 全景的 20/20/20/10 结构确实把当前、纠正、未知和方向放在一页；二稿十章覆盖了函数、外部来源、苹果案例、未知和机构化。

**具体失败：** R0 是固定基线 `9b15d…` 的前置作品，仍把任务 111 的恢复状态当作“后续候选结构”来处理；当前正式仓库已经有 111 的权威 recovery-1 终态。读者若只读 R0，会把正式状态过时地理解成未闭合。全景和二稿也没有一个正式 `PUBLICATIONS/README.md` 把五个成果连成书架，读者仍需在文件和 JSON 之间跳转。

**必修修订：** 对 111 的表述按当前正式终态重写，同时保留 R0 的取证时间边界；建立 `PUBLICATIONS/README.md`、单文件全景和完整卷的一跳/一跳路径；在正文中说明当前 111 是工程生命周期事实，而不是新的外部科学结论。

## 模拟三：检查证据的技术读者

**进入路径：** 二稿章节、来源附录和台账。

**可理解部分：** Function OS 的原始失败—修复—有限通过链条、Crossref/OpenAlex 的 metadata-only 边界和苹果 target absent 已比一般项目叙事更诚实；60 条笔记没有与卷正文整段复制。

**具体失败：** 二稿把部分目录/报告集合写成“来源”而没有在句子旁标注 source scope；某些数字的分母、版本和对象仍在附录才出现；R0 自带三份审查不能证明 112 的独立审查；台账的 `classification` 重叠，没有单独的 `output_class`，容易把研究、纠正、实验和基础设施相加。

**必修修订：** 对所有承重数字补对象、分母、版本和证据层；把目录、单文件、运行产物和外部元数据区分；建立独立的 claim audit、审查 disposition matrix 和可复现出版 manifest；重新生成台账，不把重叠分类当总数。

## 读者测试决定

R0 具备可复用的叙事和边界材料，但不能原样进入正式出版。核心失败是入口层、当前状态传播、来源 scope 和重复节奏，而不是缺少材料。最终书稿必须从问题和转折组织证据，不能只追加链接。
