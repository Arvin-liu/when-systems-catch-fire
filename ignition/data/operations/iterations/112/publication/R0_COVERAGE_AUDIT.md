# R0 覆盖审计

结论：`80 条记录足以作为可审计的成果候选池，但不是“前 100 轮逐轮完整史”。`

## 审计对象与可恢复范围

本审计逐项读取 R0 的 `01-百轮成果总台账.jsonl` 80 条记录，并与正式仓库当前 `main=302362f66dad4e8a9c9e72400f4267c12b0b0d00` 的目录、提交历史、任务 111 终态材料和标签进行交叉检查。80 个 `record_id` 全部唯一；它们是 R0 选择出的成果/资产记录，不是 Git 中 1–100 的整数迭代编号。

可恢复的材料族包括：早期问题与边界说明、统一函数/案例索引、Evidence Regime、Foundation 与非函数断言治理、MCF/PSD/ARN 架构候选、Function OS、Crossref/OpenAlex 元数据试验、苹果案例 dossier、任务 111 证据与终态材料、公共结果页、文章与出版素材、知识索引、纠正和维护记录。

当前正式仓库的 `data/operations/iterations/` 明确有 109、110、111 以及本任务的 112 intake；正式标签明确覆盖 106–111，早期材料主要通过报告、RESULTS、KNOWLEDGE、Foundation、文章和 Git 历史恢复。因而本台账采用“可恢复的连贯成果记录”而非“每个整数都必须有故事”的标准。

## 覆盖结论

| 检查项 | 结果 | 解释 |
| --- | --- | --- |
| 台账记录 | 80/80 唯一 | R0 文件内部一致；不代表 80 个独立实验 |
| 明确引用的后期任务 | 75、98–106、110、111 等 | 这些是记录中的显式任务锚点，不是全部历史轮次 |
| 早期轮次 | 以主题、报告、索引或资产组出现 | 很多没有逐轮可恢复的独立状态包 |
| 合并/分组记录 | 大量存在 | 早期框架、架构候选、出版作品集合、运营维护和开放问题均按成果族合并 |
| 维护-only / 运营记录 | 存在 | 例如 chronology、同步契约、公共链接修补和候选恢复历史，不能写成研究发现 |
| 当前终态比较 | 已纳入 task 111 recovery-1 | R0 原始记录的固定基线说明需由正式 111 终态更新 |
| 独立外部复制 | 未由本台账提供 | Crossref/OpenAlex 主要是元数据试验；Function OS 是声明范围内的工程验证 |

## 80 条记录的当前处置分布

这是按 R0 `disposition` 的审计分组，不是科学成果排名：

| 审计分组 | 数量 | 读法 |
| --- | ---: | --- |
| 在范围内保留 | 41 | 可进入成果史，但必须带当前边界、版本和证据类型 |
| 纠正或边界记录 | 13 | 旧强句、失败、target absent、状态边界或降级结果；不能写成当前正面发现 |
| 开放或未完成 | 13 | 仍是问题、出版缺口或待研究路线；不能用“完成”语气 |
| 候选/混合/维护等其他 | 13 | 需要逐条保留混合属性，不能由一个总标签代替 |

台账的分类字段是重叠的：同一记录可以同时属于研究、纠正、基础设施和出版素材。例如 Function OS 的修复既是有限实验，也是纠正成果；Foundation 的迁移既是基础设施，也是语义治理；苹果 target audit 是失败边界，却改变了实验前置规范。因此本审计不把分类计数相加为“成果总数”。

## 可见缺口与不可恢复处

1. 不能从这 80 条记录恢复每个早期整数轮次的独立问题、独立来源、独立外部证据和独立终态。
2. 很多来源路径是目录、报告集合或索引，不等于已经逐文件全文核验；来源路径数量不能代替阅读深度。
3. 公开函数与 canonical function、公开断言与 canonical claim 的数字冲突仍未由当前仓库给出唯一生成规则；出版物必须并列快照并标出未统一。
4. “研究成果”和“基础设施”在不少记录中是混合关系；若只按文件名分类会夸大研究产量。
5. 111 的恢复状态已在正式仓库闭合，但 R0 以固定基线为边界的表述不能直接复制到当前出版物；最终文本必须同时尊重 R0 的取证时点和正式当前真相。
6. OpenAlex 的 7 个 null、8 个 partial、Function OS 的有限 benchmark、苹果的 target absent 都是边界信息；它们不构成对外部世界的总否定。

## 对台账的决定

保留 80 条记录作为正式出版台账的底层材料，重写其分类和当前状态列，明确增加 `output_class`、`current_validity`、`visible_work`、`chapter_destination` 和 `claim_ceiling`。正文只吸收能够形成问题—发现—转折的记录；完整路径、提交和逐条判定放在可读但不承担正文叙事的审计包中。
