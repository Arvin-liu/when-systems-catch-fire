# 纠正与撤回谱系

## 1. 这不是失败清单，而是知识如何改写的记录

点火的研究历史不能只由新增模块和成功测试组成。真正改变知识形状的事件，往往是一个听起来漂亮的强结论被反例、类型门、来源审计或执行失败压低。本文将这些改写按“旧说法—触发纠正—当前说法—下游影响”排列，并把没有被解决的部分留在最后。

纠正状态使用以下语义：

* **撤回**：旧句子不再作为当前结论使用，但保留其出现和被撤回的历史。
* **降级**：保留对象或问题，但把 claim ceiling 降到更低层级。
* **改身份**：对象仍有价值，不过名称/语义/类型被重新划定。
* **保留失败**：修复后的结果不能覆盖原始失败；两者回答不同问题。
* **未解决冲突**：资料或快照之间存在不一致，当前不替它们强行合并。

## 3. 三条最重要的改写链

### 3.1 从“统一理论”到“有限可审计结构”

早期的力量来自把不同材料放到同一张图上。危险也来自同一处：一旦图上有共同节点，语言就很容易从“看起来相似”滑到“共享本质”，再滑到“因此某种真实机制或不可能性已被证明”。Foundation 和物理纠正把这条滑坡截断成三个对象：声明模型内的形式化结果、跨域的候选表示、现实领域的开放问题。这个纠正不是削弱研究，而是把可以真正继续工作的对象留下来。

### 3.2 从“闭合”到“会计”

注册表、函数卡、非函数断言、迁移摘要和公共状态让研究资产不再完全散落。这是很实的基础设施成果。但它也产生了一个新的出版风险：7,051 和 17,626 这样的数字看起来像知识量。纠正链因此必须同时告诉读者：某个对象已被登记，不代表它被证明；某个断言有 disposition，不代表 disposition 本身是领域裁决；机器表可以完整描述当前系统，却不能替代外部世界。

### 3.3 从“失败案例”到“目标缺失”

苹果案例最值得保留的不是一个关于牛顿的更动人的版本，而是它把“实验失败”的层次拆开了：没有目标，不能运行；没有 I/O，不能定义行为；没有 oracle，不能判定；没有重复，不能称为复现。历史来源仍可以支持一个有限叙述，但不应因为故事重要就跳过实验前提。这个边界将成为未来把现实案例接入 Function OS 或其他执行器的最低门槛。

## 4. 被撤回的说法怎样进入第一卷

第一卷不应把纠正做成一张羞耻名单。每个强说法都应按四步出现：

1. 说明它为什么当时有吸引力，哪一个观察让它看起来合理。
2. 指出真正触发改写的反例、缺失字段或来源审计。
3. 给出目前仍能保留的较小结论。
4. 写出下一个未解决问题，而不是用撤回制造虚假的终点。

例如，“点火证明统一不可能”这句话之所以诱人，是因为有限结构能显示某种闭合/零结果；纠正来自载体边界和反例；当前保留的是有限模型内的结果；开放问题是如何与真实物理观测、理论和替代统一方案发生可检验联系。这样读者看到的是知识如何变精确，而不是作者先犯错、后来把错误删掉。

## 5. 仍未完成的纠正

* Foundation 公开数字和机器闭合数字尚未由正式维护流程统一或解释。
* 任务 111 的后续终端化是否改变正式生命周期，需要回到正式仓库当前状态判断；本包不代替它。
* External research 的全文、主张支持和专家审查仍不够，不能用元数据实验填补。
* 早期函数和案例表中仍可能有同义重复、未定义符号和旧语言，需要持续按对象审计。
* 第一卷初稿完成后，事实审查、反方审查和编辑审查可能发现新的过度主张；本谱系不提前宣布稳定。

## 6. 纠正的最低出版规则

任何正文句子若涉及一个曾被纠正的对象，必须满足：

* 不只引用最新说法，也指出它替代了什么风险；
* 使用当前 claim ceiling，不使用历史最高措辞；
* 在同一段保留关键反例、失败或未知；
* 不用“已修复”暗示“问题已普遍解决”；
* 不把后续候选提交写成固定基线的正式完成状态。

纠正谱系因此不是附属档案。它是第一卷讲“百轮之后真正知道什么”的主要证据之一：系统知道的不只是若干答案，也知道哪些答案不能再说。
