# 未决项与出版边界

本文件不是任务控制文件，不驱动任何正式迭代；它只记录出版前置工程当前不能越过的边界。

## 已知未决

1. 百轮成果的“轮”不是自然科学实验的独立重复次数，而是仓库迭代、报告、修订、外部研究与维护工作的混合历史单位；出版物不得把轮数直接当作样本量。
2. Git 提交、任务状态、PR 合并和终端标签证明版本与治理轨迹，不单独证明研究命题的真实性。
3. Foundation 的注册表闭合、Function OS 的测试通过、系统图的生成成功和公开页面可达性，属于工程或治理证据，不等同于现实因果、数学证明或外部科学证据。
4. 历史函数与非函数断言存在大量 quarantine、pending、provisional、partial 和 open obligations；计数只能说明登记范围和处置状态。
5. MCF、PSD、ARN 目前是候选表示/架构与有限验证资产；跨域结构对应不是严格同构，内部关系图不是现实因果图。
6. Crossref 与 OpenAlex 试验主要支持 DOI、标题、年份和跨源书目元数据一致性，不能升级为论文内容正确或模型正确。
7. Function OS v0.2 的基准是在声明的有界符号域内进行；修复后的 `SUPPORTED_WITHIN_BOUNDED_DOMAIN` 不是通用证明系统、完备沙箱或生产就绪证明。
8. 牛顿苹果案例的固定基线证据只支持有边界的 memoir provenance；没有有效可执行 target、忠实形式化和历史因果 oracle，不能写成“已复现实现缺陷”。
9. 任务 111 在本出版基线中只能作为研究与第一阶段终端化的边界案例引用；不把后续恢复协议、候选状态或未终态投影写成任务 111 已正式完成。
10. 早期《点火》叙事与旧函数/案例表包含重复、命名漂移、强断言、未核验历史材料和被后续纠正的版本；它们必须按版本和处置阅读。
11. 之元写作法 0.4.0 是公共表达与反馈方法，不是认知科学证明，也不应把仓库术语机械替换成文学结论。
12. 读者“一页看全局”只能提供可支持认识、纠正/撤回和未决问题的压缩索引；它不能消除来源、冲突版本和证据层级。
13. 公开页面的函数身份卡计数 5,663 与基线机器 closure-summary 的 7,051 不一致；在没有 scope、去重规则和生成快照解释前，不选择其中一个作为唯一权威。
14. 公开页面的非函数断言计数 17,333 与机器 canonical claims 的 17,626 不一致；quarantine/pending 数量也分别为 3,887/4,978 与 5,581/5,801。
15. `RESULTS/CHRONOLOGY.md` 的约 287 条人类成果记录与 3,456 tracked files 是不同层级；不能把任一数字直接写成研究成果数。
16. 旧函数索引的 617 与目录约 624 个文件、Foundation 7,051 identity cards 不是同一统计对象；旧表仍是素材池而非结果集。
17. 任务 111 的固定基线研究证据和正式生命周期状态必须分开；后续恢复提交只作只读结构参考。
18. 第一卷尚未完成；任何章节的连续叙事都必须服从对应 evidence binder 的 claim ceiling。
19. Function OS 的原始 false reject 与修复后 bounded pass 必须同时出版，不能只保留 1.0。
20. Crossref/OpenAlex 的外部证据目前仍是 metadata-only；全文、主张和领域事实是未决缺口。
21. 十章 binder 已完成结构化整理，但尚未经过初稿事实审查、反方审查和编辑审查；binder 不是最终正文。
22. binder 中的“关键数字”来自不同层级和快照，正文仍需避免把数字并列造成样本量或真理量幻觉。
23. 第一卷初稿已达规模目标，但仍需事实、反方和编辑三重审查；初稿中的任何数字和强句在审查前都不是最终正文。
24. 第一卷将 5,663/7,051 和 17,333/17,626 作为并存快照写入叙事；正式维护流程仍需决定如何提供公共快照说明。
25. 初稿使用 S01–S33 来源分组，附录路径与提交是回溯入口，不代表所有来源内容都已达到 claim support。
26. 研究笔记长度按 Markdown 正文字符计为 305—481；它们仍需在三重审稿中检查是否有主题重复、来源过度压缩或边界表达不清。
27. 笔记索引引用本出版包的阶段文件时，引用的是出版层汇总，不会提升固定基线的正式远端状态。
28. 一页全景已经压缩了 70 项结论/问题/方向，但压缩不能消除来源冲突、快照差异或未决证据；三重审稿仍需检查其是否过度简化。
29. 后续研究方向是优先级建议，不是已开始的工程、正式任务或远端生命周期事件。
30. 三重审稿指出，初稿需要把“系统知道”统一降为“出版层根据记录能够支持的认识”；第二稿尚未完成前，不把初稿当最终正文。
31. 事实审查要求为每组并存数字补充范围、快照和生成路径；修订前不能用数字的并列呈现制造总量或样本量印象。
32. 反方审查要求把 Function OS、Foundation、Crossref/OpenAlex、苹果案例和 Q32 的结论严格留在各自内部验证边界；现实世界知识仍需外部证据。
33. 编辑审查要求削弱任务号、提交号和内部缩写在正文中的可见度，把它们留给附录和脚注；第二稿需重排叙事而不是逐句润色。
34. 修订清单的 P0 项必须在第二稿中处理；若某项因固定基线无法补证，只能显式保留为 `CONFLICTED`、`PARTIAL`、`OPEN` 或附录边界。
35. 第二稿已完成实质重写并达到约 30,568 个汉字，但它仍是固定基线证据的出版层综合，不是新的外部研究、同行评议或正式远端状态。
36. 第二稿中 Foundation、Function OS、外部书目和苹果案例的边界已前置到正文；来源、提交和运行细节仍需通过附录和原始基线复核，不由散文替代。
37. 最终验收已确认本目录是独立 clone、本地 push URL 为禁用占位值、无 task 112 控制文件、无 `relay/current` 文件、无正式远端写入；该确认只约束本出版包，不改变正式远端状态。

## 出版停止条件

- 找不到可定位来源时，结论只能写为 `SOURCE_UNLOCATED` 或 `NOT_RECONSTRUCTED`；不能用文件数量补足。
- 来源冲突未被逐项处理时，保持 `CONFLICTED`、`PARTIAL` 或 `OPEN`，不做平滑综合。
- 正文的强说法超过章节 claim ceiling 时，降级到候选、推断、形式化、工程验证或附录说明。
- 后续远端状态与固定基线冲突时，本包保留基线结论，并另标“后续候选/未终态”；不回写正式仓库。
- 对公开数字冲突，在正式维护者给出快照说明之前，出版稿使用“并存快照/统计口径未统一”的表述，不做平滑综合。
