# 《点火百轮之后》章节摘要

## 读者总路线

本卷不按任务编号复述，而按一个认识如何形成、被限制、被执行、被外部来源碰撞、被历史案例拒绝和重新进入公共阅读的路径组织。每章都有一个具体问题、一个可支持的认识、一个不能越过的边界。

|章节|中心问题|本章交付的认识|必须保留的边界|
|---|---|---|---|
|序|百轮是不是百次独立实验？|百轮是混合的长期运行史；主要产出是区分和自我限制|轮次不是样本量；固定基线不把任务 111 写成正式完成|
|一|点火从什么问题中诞生？|跨域相似感可以生成结构化研究问题|相似不是同构，直觉不是外部证据|
|二|为什么解释不等于证明？|证据制度领域化，claim ceiling 让结论携带上限|内部模型、测试和图边不自动成为现实真理|
|三|百轮纠正了哪些强结论？|撤回、降级、反例和失败成为知识成果|撤回旧结论不等于得到新总答案|
|四|函数与断言治理发现了什么？|Foundation 建立身份、处置、证据和谱系会计|closure 不等于 truth；公开/机器计数有快照冲突|
|五|Function OS 能做什么？|有限符号确定性域可运行，真实 parser 缺陷被发现并修复|bounded pass 不是通用 OS、生产安全或现实因果|
|六|两次外部元数据试验带回什么？|Crossref/OpenAlex 让字段纠正、匹配、partial 和 null 可见|metadata-only 不等于全文或主张支持|
|七|苹果案例何时是失败实验？|来源能支持有限 memoir association；target absent 是工程结论|没有 target 不能称执行失败，传记不自动提供唯一因果|
|八|点火仍不知道什么？|未知可被定位为外部数据、全文、干预、target、专家和快照缺口|开放问题不是已解决的问题，也不是绝望宣言|
|九|怎样走向研究机构？|研究基础设施开始承担来源、同步、传播、出版和责任|内部闭合不产生外部权威，写作法不是科学证明|
|十|下一阶段最值得研究什么？|优先做可区分、可失败、可外部审查的问题|方向不是结果，未启动路线不能写成已完成模块|
|尾声|百轮之后真正知道什么？|知道自己的证据和不知道的边界|必须让未知留在结论旁边|

## 章节间的转折

1. 第一章从“相似感”开始，第二章立即问它能不能成为证明，防止起源故事直接变成理论宣言。
2. 第二章的证据分层在第三章遇到历史强结论，通过撤回说明边界不是抽象规则。
3. 第三章把纠正带到第四章的注册表，让“撤回”成为对象状态和来源谱系，而不是一句编辑批注。
4. 第四章的会计在第五章遇到真实执行失败，说明清楚登记和实际运行仍有距离。
5. 第五章的内部运行在第六章敲外部 API 的门，读者看到工程通过不等于外部内容支持。
6. 第六章的 metadata-only 在第七章遇到历史故事和 target absent，证明来源存在、执行存在、因果存在是三扇不同的门。
7. 第七章的目标缺失把读者带到第八章未知，第九章再问如何把未知变成制度责任。
8. 第十章不宣布胜利，而是把边界转成下一阶段的研究问题和失败标准。

## 适合普通读者的阅读提示

遇到数字时问分母和对象；遇到“验证”时问是元数据、全文、工程还是因果；遇到“函数”时问输入、输出和身份；遇到“失败”时问有没有 target；遇到“机构”时问谁能从外部反驳。只要保持这五个问题，本卷的技术词汇不会变成新的权威装饰。
