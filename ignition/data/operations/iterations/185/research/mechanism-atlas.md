# Task185 Step02 — Mechanism-Level Asset Atlas

## Classification rule

This atlas groups artifacts by observable operation, not by title, directory or shared vocabulary. A validator/test establishes only the behavior it covers. “Active” means the bounded mechanism is present in the Task181 tree; it does not imply an accepted cognitive capability. Task179–181 relationships below distinguish reference/reuse, composition, explicit formalization and unresolved overlap. The archived Q37–Q39 source references point to their exact historical commit trees; the associated lab test suites were not run in this task.

## Cross-mechanism interpretation

- The pre-R0 system is not “empty”: identity, claim/evidence boundaries, provenance, retrieval/routing, observation, failure handling, governance and bounded execution are inspectable mechanisms.
- These mechanisms are distributed across different owners and surfaces. Retrieval, routing, failure retention, repository self-correction and runtime memory do not by themselves connect into a method-use → reframing → independently assessed transfer chain.
- Task179’s measurable addition is primarily explicit composition and typed transition/IR/evaluation contracts. The contracts themselves remain research-only, and their capability/calibration/evaluation fields stay unmeasured. Task181 adds an evaluation-evidence admission/isolation composition.
- Similar names do not collapse the two decision-integrity lines, causal feedback, self-correction and cognitive transition into one mechanism. Step03–Step05 will test novelty/overlap and a minimum-core candidate against these boundaries.

**Step02 status:** all 20 required mechanism families are represented; active, historical, derived, partial and research-only surfaces remain distinguishable.
