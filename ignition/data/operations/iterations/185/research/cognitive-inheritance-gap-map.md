# Task185 Step10 — Cognitive Inheritance Gap Map

## Bottom line

The repository already has substantial **data structures and governance contracts**: canonical identities/claims/evidence, derived search/routing, a provisional R0 self-model, typed Cognitive IR, transition/migration schemas, capability-interface fields, and a blind-first independent-evaluation package. The main unresolved issue is not a shortage of names or containers. It is the missing, evidenced relation from a candidate method through selection and use in context to outcome/failure and revision. Step07 found no typed `METHOD_USE` relation in the sampled route/authority surfaces; that is a bounded sample finding, not proof of repository-wide absence.

Accordingly, Task185 can establish that transition and capability descriptions are representable, but not that methods are reconstructed, used, improved, or transferred. Governance-overhead and capability/reconstruction metrics remain unmeasured. The clearest explicit real gap is matching cognitive effort to causal scale; human/Owner value choices and authority must remain outside automated optimization.

## Smallest useful next research experiment

The most discriminating low-scope research question is whether one synthetic, noncanonical method trace can preserve and retrieve: (1) candidate asset and exact source, (2) selection rationale and constraints, (3) use event, (4) observed result or failure, and (5) method revision/unknowns. Test reconstruction and false-positive handling with a small known-positive/known-negative fixture set. This would test whether a new relation is needed before adding more schema surface. It is a proposal only; Task185 did not run it.

Separate questions—cross-model calibration, evaluator-isolation behavior, governance overhead, and life-decision effort scaling—need their own designs and, where applicable, explicit Owner authorization. This handoff does not start any of them.
