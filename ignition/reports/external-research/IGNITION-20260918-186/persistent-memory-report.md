# Persistent memory: retrieval, storage, and method inheritance

## Three different objects

Generative Agents uses a simulation character's memory stream. The paper describes observations, reflections, and plans as timestamped natural-language records, retrieved with recency, relevance, and importance signals. Reflections summarize prior records and feed later planning. In the pinned code, `ConceptNode` has an `expiration` field, but it is initialized from serialized data and may be `None`; field presence alone does not prove expiration or deletion. The inspected code does not include saved simulation data.

MemGPT (2023 paper) is a context-management design: a read-only instruction block, writable working context, rolling FIFO queue, and external archival/recall storage. The paper says overflow evicts messages and creates a recursive summary, while the evicted messages remain in recall storage indefinitely and can be paged back into the prompt. This extends effective context and supports self-directed information movement through tool calls. It does not revise the memory-management method itself. The later Letta Code repository is a separate, pinned product implementation and is not treated as a reproduction of the paper system.

The pinned Letta Code snapshot uses a per-agent filesystem under `~/.letta/agents/{id}/memory`. Default blocks are `persona` and `human`; the inspected version says skills are supplied through system reminders. Memory patches require a reason and structured operations, enforce path and read-only rules, and create agent-attributed Git commits. The repository lifecycle includes clone/startup pull and post-turn push. Size, core-memory, and depth caps constrain growth; changing their tracked config requires an explicit approval override. These controls give scope, provenance, and rollback history through Git, but the inspected paths do not implement semantic deduplication or capability-profile expiry.

## What persistence changes

A later run can retrieve prior records or reload a memory file, changing its prompt context. That is durable context inheritance. A separate question is whether a later run inherits a method for deciding which records are valid, useful, stale, or safe to delete. The primary sources reviewed here do not demonstrate that second transfer across model successors, providers, or domains.

MemGPT's recursive queue summary is not equivalent to semantic consolidation: it is prompted to preserve a conversation for context continuation, while recall keeps the source messages. Letta Code's local sliding-window compaction also summarizes evicted conversation context; it is separate from Git-backed long-term memory. Generative Agents' recency score influences retrieval, not whether a memory is trustworthy. The existence of an `expiration` field in its code is not evidence that stored memories actually expire.

## Risks and boundaries

Persistent text supplied back to a model can influence later behavior. It may preserve an incorrect belief, stale instruction, or malicious text; this is a risk inference from prompt-bound retrieval, not a claim that an injection was observed in these source snapshots. Version history and explicit patch reasons help audit changes but do not establish truth or correct selection.

No self-model freshness mechanism was found in the bounded paths inspected here. Evidence freshness, recency-weighted retrieval, queue pressure, file-size limits, and memory TTL are distinct concepts. No capability claim should inherit freshness merely because its underlying record is recent or still retrievable.
