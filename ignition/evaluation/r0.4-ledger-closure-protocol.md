# R0.4 successor read-ledger closure protocol

## Boundary and versioning

R0.4 is a versioned repair of the R0.3 finalization semantics. The R0.3 schemas, validator, packet, cases, reports, and receipts remain historical and byte-stable. R0.4 uses its own task, manifest, ledger, receipt, and finalizer identities.

The certified ledger is frozen before final validation. The final validator writes only a separate deterministic local attestation receipt and is outside the certified ledger scope. Re-running finalization must return the same status and receipt without appending validator rows to the ledger.

## Entry semantics

`COGNITIVE_READ` is authorized only when the path is the packet manifest boundary object with the exact manifest digest, or is in the manifest cognitive allowlist with the exact listed digest. It has `content_exposure=YES`, no component or observed status, and a non-null digest. For an authorized cognitive read, `case_specific_information_exposed` may be either `true` or `false`; `true` is expected when the successor reads a held-out case.

`CASE_SPECIFIC_INFORMATION_EXPOSED_IS_CHANNEL_CONTEXT_NOT_CONTAMINATION_BY_ITSELF`

An authorized cognitive case read therefore derives `CLEAN`. Case-specific information exposed through `OPERATIONAL_EXECUTION` or `OPERATIONAL_STATUS_OBSERVED` derives `CONTAMINATED`; those rows must have no content exposure, no digest, and `case_specific_information_exposed=false` to remain clean. An unknown operational component or an unlisted cognitive path is contaminated. `PROHIBITED_COGNITIVE_READ` is always contaminated when its row shape proves actual content exposure.

Any row-disposition mismatch, summary mismatch, digest mismatch, malformed entry, final-validator self-reference, changed frozen ledger, or invalid receipt is `FAIL_READ_LEDGER_INVALID`.

## Scope ceiling

This protocol provides a successor-visible packet contract and a local-only trial surface. It does not authorize Successor execution, Evaluator work, canonical promotion, Foundation or Current mutation, R1, MetaRSI, Model-RSI, weight training, Ready, merge, rebase, amend, squash, or force-push. A future Owner task must explicitly authorize any successor trial; the default R0.4 trial remains local-only with no commit or push from the Successor.
