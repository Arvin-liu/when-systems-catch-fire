# 失败类型学初稿

## 一、失败类型总表

本次初稿建立 12 种失败类型：

1. 材料错误
2. 边界选错
3. 尺度错配
4. 函数过度泛化
5. 同构误判
6. 证据等级不足
7. AI 过度解释
8. L2 推论误写成 L5 结论
9. 学科证据制度误配
10. 观察者位置错误
11. 把局部机制误写成全局规律
12. 把历史叙事误写成因果定律

这些失败类型不是孤立的错误清单，而是点火框架的“负向结构表”。它们用于提醒使用者：结构性推论本身并不等于外部成立，任何函数、案例和证据都可能因为边界、尺度、证据制度或观察位置错误而失真。

## 二、12 张失败类型卡片

### 1. 材料错误

材料错误指输入本身有误，包括案例、史料、数据、转述或对象定义不准确。

**典型表现：**
- 事实基础不可靠；
- 案例来源不清；
- 关键数据缺失或错误；
- 叙述对象被混淆。

**触发原因：**
- 资料收集不完整；
- 来源未核查；
- AI 误读文本；
- 人类整理时发生转写错误。

**影响函数：**
- 直接污染 `C(x,y)`、`I_iso(A,B)` 和案例函数；
- 使后续结构判断建立在错误前提上。

**修正方式：**
- 回到原始材料；
- 重新核查来源；
- 将不可靠条目标记为 `pending`；
- 必要时移出案例主库。

### 2. 边界选错

边界选错指系统范围、分析对象或时间跨度设定错误。

**典型表现：**
- 把局部现象当作全局机制；
- 把短期波动当作长期规律；
- 把观察者位置混入对象本身。

**触发原因：**
- 系统定义不清；
- 领域层级混用；
- 时间尺度或空间尺度设定不当。

**影响函数：**
- 破坏 `L_meta`；
- 误导 `P_meta`；
- 让跨域同构看起来成立，实际上只是边界错位。

**修正方式：**
- 重新定义系统边界；
- 明确内部/外部、输入/输出、时间/空间尺度；
- 必要时拆分为多个子系统。

### 3. 尺度错配

尺度错配指分析层级与对象层级不对应。

**典型表现：**
- 宏观解释套到微观现象；
- 微观机制硬推宏观规律；
- 局部样本被过度外推。

**触发原因：**
- 过度抽象；
- 样本过少；
- 忽略层级差异。

**影响函数：**
- 误伤 `M(B_n)` 的收敛判断；
- 让“看似收敛”掩盖实际不稳。

**修正方式：**
- 补齐层级说明；
- 将命题限定在正确尺度；
- 分别标注局部、区域、全局结论。

### 4. 函数过度泛化

函数过度泛化指一个函数被推广到超出其适用范围的领域。

**典型表现：**
- 一个有效函数被当作通用解释器；
- 函数在新场景中失效却仍被重复使用；
- 函数边界被忽略。

**触发原因：**
- 对函数适用条件理解不足；
- 想要统一解释过多现象；
- 过度相信单一机制。

**影响函数：**
- 破坏函数族的可信度；
- 影响函数依赖图；
- 容易引发错误的函数合并或升级建议。

**修正方式：**
- 添加适用条件；
- 拆分函数族；
- 给函数加上失败边界。

### 5. 同构误判

同构误判指两个系统看起来相似，但实际上不存在可比结构映射。

**典型表现：**
- 仅凭表面相似就判定同构；
- 将类比误当作等价；
- 把结构相似当成机制相同。

**触发原因：**
- 过度追求跨域映射；
- 忽略证据链；
- 对 `I_iso(A,B)` 过度乐观。

**影响函数：**
- 直接影响同构函数；
- 可能把弱类比写成强同构；
- 误导后续机制生成。

**修正方式：**
- 区分类比、映射、同构；
- 要求明确映射条件；
- 对弱同构默认 `pending`。

### 6. 证据等级不足

证据等级不足指推论的证据强度与断言等级不匹配。

**典型表现：**
- 用 L1-L2 推论冒充 L4-L5 结论；
- 没有外部验证却给出终局判断；
- 证据缺口被忽略。

**触发原因：**
- 断言冲动；
- 想快速给出结论；
- 忽略证据制度库。

**影响函数：**
- 直接影响所有高风险领域；
- 会污染 README、案例表和对外表述。

**修正方式：**
- 强制回到 `pending`；
- 补齐证据链；
- 重新标注断言等级。

### 7. AI 过度解释

AI 过度解释指模型把结构性推论扩写成超出证据范围的结论。

**典型表现：**
- 过度流畅的总结；
- 看似完整但缺少证据；
- 自动补全不存在的逻辑链。

**触发原因：**
- 提示词鼓励“给出结论”；
- 缺少反例约束；
- 没有证据制度门槛。

**影响函数：**
- 容易污染 AI 输出协议；
- 让 `pending` 被覆盖为 `true`。

**修正方式：**
- 引入强制反例；
- 要求引用证据等级；
- 输出前先检查 `pending` 条件。

### 8. L2 推论误写成 L5 结论

L2 推论误写成 L5 结论指内部结构性判断被当作外部实证成立。

**典型表现：**
- 结构性统一写成“已经证明”；
- 候选机制写成“最终机制”；
- 框架内判定写成外部验证。

**触发原因：**
- 语言不够谨慎；
- 标注缺失；
- README 与正文混用。

**影响函数：**
- 影响项目公信力；
- 误导读者理解项目定位；
- 增加高风险领域误读。

**修正方式：**
- 强制写清断言等级；
- 结构性推论与实证结论分栏；
- 无外部证据时一律保守。

### 9. 学科证据制度误配

学科证据制度误配指把一个学科的证据标准硬套到另一个学科上。

**典型表现：**
- 用数学证明标准要求历史学；
- 用实验要求替代文学解释；
- 用史料标准替代工程测试。

**触发原因：**
- 不理解学科差异；
- 把所有领域压成同一格式；
- 证据制度库缺失或未使用。

**影响函数：**
- 破坏跨学科输出；
- 让结论要么过严，要么过松。

**修正方式：**
- 查阅证据制度库；
- 按学科重设成立标准；
- 必要时单独建子协议。

### 10. 观察者位置错误

观察者位置错误指把分析者的视角、介入程度或立场误当作系统内部属性。

**典型表现：**
- 把观察偏差当作系统特征；
- 把解释框架当作对象结构；
- 把作者立场当作客观事实。

**触发原因：**
- 元层与对象层混淆；
- 缺少观察者标注；
- 未区分描述和解释。

**影响函数：**
- 影响 `P_meta` 和 `L_meta`；
- 容易把元协议投影误成事实本身。

**修正方式：**
- 显式标注观察者位置；
- 分开对象层、元层和解释层；
- 记录立场与假设。

### 11. 把局部机制误写成全局规律

把局部机制误写成全局规律指有限条件下成立的机制被扩展成普遍定律。

**典型表现：**
- 个案经验上升为普遍法则；
- 某领域规律被跨域复制；
- 局部成立被当成全局必然。

**触发原因：**
- 样本不足；
- 证据外推过度；
- 缺少失败边界。

**影响函数：**
- 影响函数泛化；
- 影响案例到结论的迁移。

**修正方式：**
- 标明适用范围；
- 加入失败边界；
- 把“局部机制”保留为候选而非定律。

### 12. 把历史叙事误写成因果定律

把历史叙事误写成因果定律指把叙述结构或故事化解释当作强因果定律。

**典型表现：**
- 故事很顺，但证据不足；
- 因果链条过于整齐；
- 叙事张力掩盖了史料争议。

**触发原因：**
- 叙事偏好；
- 选择性材料；
- 史料互证不足。

**影响函数：**
- 误导历史学和社会科学分析；
- 造成“看起来合理”的假因果。

**修正方式：**
- 回到史料互证；
- 将叙事与因果分开；
- 不足时使用 `pending`。

## 四、失败案例反向修正机制

失败案例进入失败案例库后，应按以下流程处理：

1. 判断失败类型；
2. 定位相关函数或函数族；
3. 识别是材料错误、边界错误、尺度错误还是证据问题；
4. 判断应修正函数、降级函数、合并函数、删除候选，还是只改案例标注；
5. 同步更新函数表、案例表、证据制度库、AI 输出协议和边界说明；
6. 所有高风险修正必须由人类维护者复核；
7. 在版本记录中记下这次失败修正。

| 证据等级不足 | 断言过强 | 证据制度库 | `pending` |
| AI 过度解释 | 模型幻觉 | AI 输出协议 | 加反例 / 降级 |
| L2 误写成 L5 | 结构性推论冒充实证 | README / 文档 | 重标断言等级 |
