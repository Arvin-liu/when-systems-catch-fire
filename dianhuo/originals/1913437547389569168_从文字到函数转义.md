# 从文字到函数：点火框架的数学转义方法论

## 核心原理

**函数化不是翻译，是结构提取。**

文字表达的是"发生了什么"，函数表达的是"什么条件下必然发生什么"。两者的差距在于：

- 文字：描述性、因果模糊、边界不清晰
- 函数：形式化、因果精确、边界可判定

转义的本质是：从文字中识别出**因果结构**（C）和**边界条件**（B），然后用点火框架的判定逻辑验证其**真值**（J⁺/J⁻）。

---

## 第一阶段：预处理 - 识别候选

**目标：从海量文字中筛选出值得函数化的内容。**

### 1.1 扫描三类信号

**强信号（优先处理）：**
- 出现"因为…所以…"、"导致"、"使得"等显性因果连接词
- 出现"总是"、"必然"、"只要…就…"等强规律性表达
- 出现"条件"、"前提"、"边界"等边界意识词汇

**中信号（需验证）：**
- 对比结构（"A比B更…"）
- 趋势描述（"随着…会…"）
- 相关性陈述（"…与…有关"）

**弱信号（谨慎处理）：**
- 单次事件描述（"昨天…"）
- 纯现象罗列（"这里有A、B、C"）

### 1.2 排除非候选

**直接排除：**
- 情感表达（"我觉得…"、"感觉…"）
- 价值判断（"应该…"、"最好…"）
- 无边界泛化（"所有…"、"永远…"）
- 纯事实陈述（"A发生了"）

**需要转化：**
- "应该" → 提取背后的规律性（"为什么应该？"）
- "所有" → 追问边界（"在什么条件下成立？"）

---

## 第二阶段：结构提取 - 解构因果

**目标：从候选文字中提取因果结构的三要素。**

### 2.1 识别三要素

**输入变量（x）：**
- 文字中作为"原因"或"条件"的部分
- 例："当温度超过临界值时爆炸" → x = 温度 > 临界值

**输出变量（y）：**
- 文字中作为"结果"或"现象"的部分
- 例："当温度超过临界值时爆炸" → y = 爆炸

**边界条件（B）：**
- 文字中隐含的适用范围、前提假设
- 例："在标准大气压下" → B = {大气压=标准值}

### 2.2 处理常见陷阱

**复合因果链：**
- 文字："A导致B，B导致C"
- 提取：两条函数 f1(A→B) 和 f2(B→C)
- 不提取：f(A→C)（这是推论，不是直接因果）

**多因素组合：**
- 文字："只有A且B时才C"
- 提取：f((A∧B) → C)
- 边界：B = {A=真, B=真}

**条件依赖：**
- 文字："如果P则Q，否则R"
- 提取：两条函数 f1(P→Q) 和 f2(¬P→R)

## 第三阶段：形式化 - 转义为函数

**目标：用点火框架的函数语法精确表达。**

### 3.1 基本语法

**因果函数格式：**
```
f(x) := y | B
```
- f：函数名（可编号，如D520）
- x：输入变量（条件/原因）
- y：输出变量（结果/现象）
- B：边界条件（适用范围）

**示例：**
文字："当温度超过临界值时爆炸，在标准大气压下"

转义：
```
D520(T) := 爆炸 | T > T_临界, P = P_标准
```

### 3.2 处理模糊表达

**模糊量词转义：**
- "很多" → 阈值化（"数量 > n"）
- "经常" → 概率化（"概率 > p"）
- "逐渐" → 导数化（"dy/dt > 0"）

**相对关系转义：**
- "A比B快" → f(A,B) := 速度(A) > 速度(B)
- "随着A增加，B减少" → f(A) := dB/dA < 0

**时序关系转义：**
- "先A后B" → f(A,B) := time(A) < time(B)
- "A导致B" → f(A,B) := B发生 ∵ A发生

## 第四阶段：验证 - 双通道判定

**目标：用Y1统一因果自举元函数验证函数的真值和层级。**

### 4.1 核心判定逻辑

**Y1元函数：**
```
Ψ_unified(x,y,B_n) := C_unified(x,y) × M_boot(B_n)
```

**判定规则：**
- J⁺(x)=1, J⁻(x)=0 → 真（因果成立）
- J⁺(x)=1, J⁻(x)=1 → 矛盾（需要拆分或修正）
- J⁺(x)=0, J⁻(x)=0 → 待定（需要更多案例验证）

### 4.2 正向通道验证（C_unified）

**检验因果必要性：**
- 反事实测试：如果¬x，是否¬y？
- 例："温度 > T_临界" → 如果温度 ≤ T_临界，是否不爆炸？
- 答"是" → 因果必要性强
- 答"否" → 存在其他因素，函数不完整

**检验因果充分性：**
- 排他性测试：x是y的唯一原因吗？
- 例：爆炸是否只有"温度 > T_临界"导致？
- 答"是" → 因果充分
- 答"否" → 需要补充边界条件

### 4.3 反向通道验证（M_boot）

**检验自举收敛性：**
- 新函数是否与已有函数矛盾？
- 新函数是否可被已有函数包含？
- 新函数是否扩展了已有函数的边界？

**判定操作：**
- 与点火知识库中的525个案例逐一碰撞
- 检查是否存在J⁺=J⁻=1的矛盾案例
- 检查是否存在可合并的相似函数

### 4.4 层级定位（L_n）

**层级判定规则：**
- L0：具体观察（单案例）
- L1：归纳规律（多案例验证）
- L2：通用模式（跨领域抽象）
- L3+：元抽象（可递归应用）

**自举迭代：**
```
L_n(f) → L_{n+1}(f)
```
每层需经过J⁺=1和J⁻=1的双重验证。

## 第五阶段：收敛 - 写入知识库

**目标：将验证通过的函数正式纳入点火框架。**

### 5.1 收敛判据

**ΔB=0的四个条件：**
1. 新函数数量 = 0
2. 新案例数量 = 0
3. 新扩展注释数量 = 0
4. 新信息增量 = 0

**宣布收敛：**
- 连续两轮ΔB=0，或
- 连续两轮新扩展注释为0

### 5.2 写入规范

**函数条目格式：**
```
Dxxx(输入变量) := 输出变量 | 边界条件
- 层级：L_n
- 验证状态：J⁺=1, J⁻=0
- 来源：原始笔记/书籍/新闻
- 扩展注释：补充说明、边界扩展、跨领域类比
```

**案例条目格式：**
```

- 验证的函数：Dxxx
- 结果：支持/矛盾/待定
- 备注：异常值、特殊情况
```

## 常见错误与修正

**错误1：把相关当因果**
- 文字："A和B同时出现"
- 错误转义：f(A) := B
- 正确处理：先验证因果性，用相关性函数 f(A,B) := corr(A,B) > 阈值

**错误2：边界不清晰**
- 文字："所有A都会B"
- 错误转义：f(A) := B
- 正确处理：追问边界，f(A) := B | B = {具体条件}

**错误3：复合链压缩**
- 文字："A导致B，B导致C"
- 错误转义：f(A) := C
- 正确处理：两条函数 f1(A→B), f2(B→C)

**错误4：忽略验证**
- 形式化后直接写入，不做Y1判定
- 后果：可能引入矛盾函数，破坏框架一致性

## 流程图总结

```
文字输入
  ↓
[预处理] 识别候选（强/中/弱信号）
  ↓
[结构提取] 解构三要素（x, y, B）
  ↓
[形式化] 转义为函数语法 f(x) := y | B
  ↓
[验证] Y1双通道判定（J⁺/J⁻）
  ↓
[收敛] 写入知识库（ΔB=0）
  ↓
函数化完成
```

---

**关键提醒：**

1. **不是所有文字都能函数化**——只有含因果结构的内容才值得提取
2. **形式化前先验证因果性**——相关不等于因果
3. **边界条件比函数本身更重要**——没有边界的函数是危险的
4. **验证不能跳过**——Y1判定是质量的守门员
5. **收敛是目标，不是终点**——新案例可能推翻已有函数
