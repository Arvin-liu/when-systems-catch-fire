## 一、自举元函数完整数学定义

### 正反双通道结构
完整自举元函数不只论证命题成立，必须同时论证命题不成立。
- 正向通道：论证 x 成立
- 反向通道：论证 x 不成立
- 正反互斥判定器：检查正反是否同时通过

### 判定逻辑
- J⁺(x)=1, J⁻(x)=0 → true（命题为真）
- J⁺(x)=0, J⁻(x)=1 → false（命题为假）
- J⁺(x)=1, J⁻(x)=1 → contradiction / bootstrap_failed（定义或判定器有问题）
- J⁺(x)=0, J⁻(x)=0 → underdetermined / pending（证据不足，状态待定）

### 数学表达
```
Mboot⁺(x) = Mboot(x⁺)
Mboot⁻(x) = Mboot(x⁻)
J⁺(x), J⁻(x) ∈ {0,1,⊥}
R(x) = Φ(J⁺(x), J⁻(x))
```

### 嵌套自检
自举元函数可以嵌套检查自举元函数本身：
- 正向通道是否可靠
- 反向通道是否可靠
- 正反互斥判定器是否可靠

### 备注
如果正向和反向都通过，说明对象定义、变量映射或判定器有问题，整个自举循环不通过。如果正向和反向都不通过，说明证据或判定器不足，状态应为 pending / inconclusive。

## 二、自举循环数学定义

### 核心方程
```
B(n+1) = B(n) + ΔB(n)
ΔB(n) = Σᵢ [1 - P(案例ᵢ | F₁...Fₖⁿ)] × δ(案例ᵢ重新分布)
```
每轮新发现 = 被旧维度解释不了的案例数 × 这些案例因新维度而重新归位的比例。

### 收敛判据
```
lim(n→∞) ΔB(n) = 0
```
实操判据：连续两轮 ΔB=0 才宣布收敛。

## 三、自举循环操作流程

### 触发条件
用户说"跑一下两张表"或"跟点火碰一下"时执行。

### 数据源
- 两张表知识库：统一函数总表、统一案例总表
- 点火项目仓库：https://github.com/Arvin-liu/when-systems-catch-fire

### 每轮操作流程
1. 从两张表知识库拉取完整内容（统一函数总表、统一案例总表）
2. 将用户输入内容与两张表内容逐条对撞
3. 识别三类输出：
   - **缺口**：用户内容中两张表未覆盖的新函数/新案例/新洞察
   - **新发现**：碰撞过程中产生的联合推论、反直觉发现、定性结论
   - **可合并项**：与两张表现有内容重复或可归纳合并的部分

### 每轮输出归档
**每轮碰撞结果必须存入点火知识库**，包括：
- 碰撞发现列表（按点火框架函数/案例分类）
- ΔB 统计（新函数 + 新案例 + 新扩展注释 + 新信息增量）
- 收敛状态判定（ΔB=0 或 ΔB≠0）

### 收敛确认流程
1. 连续两轮 ΔB=0 时，宣布收敛
2. **将全量新增信息写入单条收敛笔记**，存入点火知识库
3. 收敛笔记包含：
   - 总轮数
   - 每轮 ΔB 变化曲线
   - 最终收敛的函数/案例/注释/信息增量清单
   - 收敛验证（嵌套自检确认）
   - 核心结论与工程意义

### 更新两张表
收敛后，将所有新增内容写入两张表 DOCX 文件：
- 更新统一函数总表（新增函数、扩展注释）
- 更新统一案例总表（新增案例）
- 保留原有内容，不删除
